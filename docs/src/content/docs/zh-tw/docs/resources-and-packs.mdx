翻完一張 Minecraft Java 版冒險地圖後，你可以依發布需求決定要把譯文「直接放進地圖」還是「做成資源包」。這頁幫你快速選對方案並示範怎麼操作。

## 1. 我該選哪一種輸出方式？

| 交付方式 | 使用指令 | 會改地圖存檔嗎？ | 會產出資源包或語言檔嗎？ | 最推薦用在什麼情況 |
| --- | --- | --- | --- | --- |
| **直接把譯文寫進地圖** | `translate plan --direct` -> `apply` | 會 | 不會 | **對玩家最省事。** 載入地圖就能直接看到譯文，完全不需要掛載資源包。 |
| **多語言地圖（翻譯鍵 + 資源包）** | `translate plan --keys` -> `apply` | 會 | 會 | 希望同一張地圖支援多國語言，玩家切換 Minecraft 語言就能自動換字幕。 |
| **只匯出獨立資源包** | `translate create-pack` | 不會（需指定外部 `--output`） | 會（`.zip` 或資料夾） | 不改動地圖本身的 NBT，只把譯文打包或合併成客戶端資源包。 |
| **只匯出純語言 JSON 檔** | `translate export-lang` | 不會（需指定外部 `--output`） | 會（例如 `en_us.json`、`zh_tw.json`） | 只需要原始 `.json` 語言檔交給其他翻譯或資源包作者使用。 |
| **單次全文抽成翻譯鍵** | `convert <world> --lang <locale>` | 會（加 `--apply` 時） | 會 | 不經分頁翻譯，直接把現有地圖的文字一次抽離成翻譯鍵與語言檔。 |

## 2. 把翻譯進度轉成翻譯鍵與資源包（`translate plan --keys`）

如果希望地圖支援多語言，`--keys` 會把每一筆文字換成翻譯鍵（例如 `map.<代碼>`），同時在**同一份計畫**中產生對應的 `.json` 語言檔（以下以目標語言 `zh_tw` 為示範）：

```powershell title="PowerShell"
New-Item -ItemType Directory -Path 'D:\Translate' -Force | Out-Null

.\nbtcli.exe translate plan 'D:\WorldCopy' `
  --session-id '6f9619ff-8b86-d011-b42d-00cf4fc964ff' `
  --revision 2 `
  --keys `
  --prefix map. `
  --language-output 'resources.zip#assets/adventure/lang/zh_tw.json' `
  --output 'D:\Translate\keys-plan.json'
```

接著關閉 Minecraft，執行 `.\nbtcli.exe apply 'D:\WorldCopy' --plan 'D:\Translate\keys-plan.json' --world-offline` 套用。

### `--language-output` 支援的三種寫法

`--language-output` 用來指定語言檔要放在世界內的哪裡（請將 `zh_tw.json` 換成該翻譯進度綁定的目標語言檔名）：

- **`generated.zip#assets/example/lang/zh_tw.json`**：自動新建一個 `.zip` 資源包。
- **`resources.zip#assets/example/lang/zh_tw.json`**：安全合併進地圖原本就有的 `resources.zip`，原有的材質、音效與 `pack.png` 都會完整保留。
- **`resourcepacks/client/assets/example/lang/zh_tw.json`**：寫入或合併到資料夾型資源包。

<FileTree>
- D:\Exports\Packs\adventure-pack.zip
  - pack.mcmeta
  - pack.png (合併時自動保留原圖示)
  - assets/
    - adventure/
      - lang/
        - **en_us.json** (原始語言文字範例)
        - **zh_tw.json** (目標語言譯文範例)
</FileTree>

:::note[語言檔名要和目標語言一致]
`--language-output` 結尾的語言檔名（例如 `zh_tw.json`）必須跟翻譯進度綁定的目標語言一致，且既有資源包的 `pack.mcmeta` 版本必須相容你的世界格式家族。
:::

## 3. 匯出獨立語言檔或資源包（`export-lang` 與 `create-pack`）

所有文字都翻完（`pending: 0`）後，這兩個指令可以幫你輸出獨立的 `.json` 語言檔或完整資源包，**完全不修改地圖內的遊戲 NBT**。

:::caution[記得明確加上外部 `--output` 資料夾]
如果省略 `--output`，`export-lang` 預設會寫入世界內的 `.nbtcli.language`，`create-pack` 則預設會寫入世界根目錄或 `<world>\resourcepacks`。只要明確加上外部路徑（例如 `--output 'D:\Exports\Packs'`），就能確保原世界資料夾完全不被動到。
:::

<Tabs syncKey="pack-export-mode">
  <TabItem label="建立或合併客戶端資源包 (create-pack)">

```powershell title="PowerShell（以 en_us 翻成 zh_tw 為例）"
New-Item -ItemType Directory -Path 'D:\Exports\Packs', 'D:\Plans' -Force | Out-Null

# 先預覽（要直接輸出檔案時，加上 --apply --world-offline）
.\nbtcli.exe translate create-pack 'D:\WorldCopy' `
  --session-id '6f9619ff-8b86-d011-b42d-00cf4fc964ff' `
  --revision 2 `
  --original-lang en_us `
  --target-lang zh_tw `
  --prefix map. `
  --name 'adventure-pack.zip' `
  --format zip `
  --pack-format 34 `
  --merge 'D:\BaseAssets\base-pack.zip' `
  --output 'D:\Exports\Packs' `
  --plan-output 'D:\Plans\create-pack-plan.json'
```

  </TabItem>

```powershell title="PowerShell（以 en_us 翻成 zh_tw 為例）"
  --original-lang en_us `

```

### 常用選項說明

- **`--original-lang` 與 `--target-lang`**：預設沿用翻譯進度綁定的 `sourceLocale` 與 `targetLocale`，且兩者不可相同。若進度的來源語言為 `und`，匯出成雙語語系檔時**必須**以 `--original-lang <語言>` 明示來源。
- **`--output <資料夾>` vs. `--plan-output <計畫檔>`**：`--output` 指定匯出的 `.zip` 或 `.json` 要放哪裡；`--plan-output` 則是另存預覽計畫檔的位置。
- **`--format zip|directory`**：選擇打包成單一 `.zip`（直接丟進 Minecraft 的 `resourcepacks` 資料夾就能用）或是解開的資料夾。
- 匯出到世界外、或目標世界的預設資源包格式無法自動驗證時，請填寫 **`--pack-format <版本號>`**。常見代表版本值：1.20.1 用 `15`、1.20.2 用 `18`、1.20.4 用 `22`、1.20.5 用 `32`、1.21 用 `34`、1.21.5 用 `55`、1.21.9 用 `69`、1.21.11 用 `75`、26.1-snapshot-6 用 `80`。完整 17 個格式家族見 **[支援版本與疑難排解](../support-and-troubleshooting/)**。
- **`--merge <路徑>`**：選用！把新翻好的語言檔合併進你原本的材質／音效資源包中，貼圖、音效與 `pack.png` 都會保留；若遇到衝突的翻譯鍵會主動提醒並中止，不會偷蓋掉原檔。

<details>
<summary>進階：稍後再套用另存的資源計畫檔</summary>

想直接寫出檔案時，直接在 `export-lang` 或 `create-pack` 結尾加上 `--apply --world-offline` 最方便。如果是先存 `--plan-output` 稍後再交給 `nbtcli apply`，請直接使用預覽輸出 JSON 中回傳的 `commitArguments`（當預覽時目標子資料夾尚未建立時特別重要）。

## 4. 不開翻譯進度，一次全文轉翻譯鍵（`convert`）

如果你只是想把現有英文地圖裡的文字全部抽離成翻譯鍵 + `en_us.json`，不想建立分頁翻譯進度，直接用 `convert`：

```powershell title="PowerShell"
New-Item -ItemType Directory -Path 'D:\Plans' -Force | Out-Null

# 先預覽轉換計畫
.\nbtcli.exe convert 'D:\WorldCopy' `
  --lang en_us `
  --prefix nbt. `
  --language-output 'resources.zip#assets/nbt/lang/en_us.json' `
  --output 'D:\Plans\convert-plan.json'
```

- 預設情況下，一模一樣的文字出現在多處會共用同一個翻譯鍵；若希望每個出現位置都有獨立翻譯鍵，請加上 **`--keepdup`**。
- 加上 `--apply --world-offline` 正式轉換時，`convert` 預設會先幫你存一份完整世界備份（只有加 `--no-backup` 才會略過這份額外完整備份，底層寫前備份與中斷復原仍全程運作）。

## 5. 翻譯實體名稱時，避免把地圖指令方塊搞壞

很多冒險地圖的指令方塊會用名字來抓特定的盔甲座或 NPC，例如 `@e[name="QuestGuide"]`。如果只把實體的名字翻譯成其他語言，卻沒同步改到抓它的指令，劇情或機關就可能卡關！

因此 NBTExplorerCLI 內建兩層保護：
1. **預設安全攔截**：一般執行 `translate plan` 或 `convert` 時，如果改到具有識別用途的實體或盔甲座名稱，預設會先攔截提醒，防止意外破壞地圖機關。
2. **安全同步引用（`--synchronize-references`）**：在 `translate plan --direct` 模式下，如果你確定要連實體名稱一起翻譯，並讓工具自動同步更新同範圍內抓到它的指令，請加上 `--synchronize-references`：

```powershell title="PowerShell"
.\nbtcli.exe translate plan 'D:\WorldCopy' `
  --session-id '6f9619ff-8b86-d011-b42d-00cf4fc964ff' `
  --revision 2 `
  --direct `
  --synchronize-references `
  --output 'D:\Translate\direct-sync-plan.json'
```

只要範圍內有任何無法證明可安全改寫的動態或模糊指令，工具就會在改動任何檔案前先安全中止。
