在翻譯或處理 Minecraft Java Edition 世界文字時，**NBTExplorerCLI** 同時支援**直接修改世界存檔內容**與**匯出獨立資源包／語言檔**。先了解各模式的差異，能協助您為地圖選擇最合適的交付方式。

## 1. 五種本地化與轉換模式比較

| 工作流模式 | 使用命令 | 是否修改世界內遊戲 NBT/JSON？ | 是否產出語言檔或資源包？ | 適用情境 |
| --- | --- | --- | --- | --- |
| **直接替換世界文字** | `translate plan --direct` -> `apply` | 是（原地替換世界內的文字） | 否 | 希望玩家直接載入地圖就能看到譯文，無須額外掛載資源包。 |
| **工作階段翻譯鍵轉換** | `translate plan --keys` -> `apply` | 是（將世界文字改為 `translate` 鍵） | 是（寫入或合併對應的 `.json` 語言檔） | 希望地圖改用翻譯鍵（如 `map.<digest>`），並搭配內嵌或資料夾資源包切換語言。 |
| **單次全文轉翻譯鍵** | `convert <world> --lang <locale>` | 是（加上 `--apply` 時） | 是（預設輸出至 `resources.zip#assets/nbt/lang/<locale>.json`） | 不透過分頁翻譯工作階段，想一次將現有世界文字抽離成翻譯鍵與語言檔。 |
| **匯出獨立語言檔** | `translate export-lang` | 不改遊戲 NBT（省略 `--output` 時會寫入世界內的 `.nbtcli.language`） | 是（輸出原文與譯文 `.json` 語言檔） | 只想從已完成的工作階段取得語言檔，不改動世界內的遊戲 NBT。 |
| **建立獨立資源包** | `translate create-pack` | 不改遊戲 NBT（省略 `--output` 時會寫入世界目錄或 `resourcepacks/`） | 是（建立或合併 ZIP／資料夾資源包） | 想將翻譯成果打包成客戶端資源包，或安全合併至既有的美術資源包中，而不改動遊戲 NBT。 |

## 2. 工作階段翻譯鍵計畫（`translate plan --keys`）

當您使用 `--keys` 產生工作階段計畫時，所有已翻譯的槽位都會從純文字轉為 Minecraft `translate` 翻譯鍵（例如 `map.<slot-digest>`），且對應的語言檔會納入**同一份原子修改計畫**中一併驗證與寫入（執行前請確認外部輸出目錄如 `D:\Translate` 已存在）：

```powershell title="PowerShell"
New-Item -ItemType Directory -Path 'D:\Translate' -Force | Out-Null
.\nbtcli.exe translate plan 'D:\WorldCopy' `
  --session-id 6f9619ff-8b86-d011-b42d-00cf4fc964ff `
  --revision 2 `
  --keys `
  --prefix map. `
  --language-output 'resources.zip#assets/adventure/lang/zh_tw.json' `
  --output 'D:\Translate\keys-plan.json'
```

### `--language-output` 支援的三種目標路徑與資源包結構

`--language-output` 用於指定相對於世界目錄的語言檔或壓縮包內部項目：

- **`generated.zip#assets/example/lang/zh_tw.json`**：若該 ZIP 資源包尚不存在，會自動建立新的資源包壓縮檔。
- **`resources.zip#assets/example/lang/zh_tw.json`**：將語言檔安全合併至世界既有的 `resources.zip` 中，並完整保留壓縮包內的其他資產與 `pack.png`。
- **`resourcepacks/client/assets/example/lang/zh_tw.json`**：將語言檔寫入或合併至世界內的資料夾型資源包。

<FileTree>
- D:\Exports\Packs\adventure-pack.zip
  - pack.mcmeta
  - pack.png (合併時自動保留既有圖示)
  - assets/
    - adventure/
      - lang/
        - **en_us.json** (原始語言字串)
        - **zh_tw.json** (目標翻譯字串)
</FileTree>

> [!IMPORTANT]
> `--language-output` 路徑中的語言檔名（如 `zh_tw.json`）必須與工作階段的目標語言一致，且既有資源包的 `pack.mcmeta` 格式必須與該世界的 `DataVersion` 相容。

## 3. 匯出獨立語言檔與資源包（`export-lang` 與 `create-pack`）

當所有槽位皆已完成翻譯或標記為保留原文時，這兩個命令可先預覽要產出的資源檔案；若加上 `--apply --world-offline`，則會直接輸出資源檔案，且**不會修改世界內的遊戲 NBT，也不會將工作階段封存**。若省略 `--output`，`export-lang` 預設會寫入世界資料夾內的 `.nbtcli.language`，而 `create-pack` 則依 Profile 寫入世界根目錄或 `resourcepacks/`（`java-dimensions-namespaced` 會使用 `resourcepacks/`）。若要讓整個世界資料夾完全維持不變，請明確指定外部 `--output`，並事先準備好世界資料夾外的既有父目錄（如 `D:\Exports` 與 `D:\Plans`）。

<Tabs syncKey="pack-export-mode">
  <TabItem label="匯出獨立語言檔 (export-lang)">

```powershell title="PowerShell"
New-Item -ItemType Directory -Path 'D:\Exports', 'D:\Plans' -Force | Out-Null
# 預覽獨立語言檔匯出並儲存計畫檔
.\nbtcli.exe translate export-lang 'D:\WorldCopy' `
  --session-id 6f9619ff-8b86-d011-b42d-00cf4fc964ff `
  --revision 2 `
  --original-lang en_us `
  --target-lang zh_tw `
  --prefix map. `
  --output 'D:\Exports\LangFiles' `
  --plan-output 'D:\Plans\export-lang-plan.json'
```

若要直接寫入檔案，請加上 `--apply --world-offline`（或使用 `nbtcli apply` 套用已儲存的 `--plan-output` 計畫檔）。

  </TabItem>
  <TabItem label="建立或合併資源包 (create-pack)">

```powershell title="PowerShell"
New-Item -ItemType Directory -Path 'D:\Exports', 'D:\Plans' -Force | Out-Null
.\nbtcli.exe translate create-pack 'D:\WorldCopy' `
  --session-id 6f9619ff-8b86-d011-b42d-00cf4fc964ff `
  --revision 2 `
  --original-lang en_us `
  --target-lang zh_tw `
  --prefix map. `
  --name 'adventure-pack.zip' `
  --format zip `
  --pack-format 34 `
  --merge 'D:\BaseAssets\base-pack.zip' `
  --output 'D:\Exports\Packs' `
  --plan-output 'D:\Plans\create-pack-plan.json'
```

  </TabItem>
</Tabs>

`create-pack` 重要參數說明：

- **`--output <目錄>` vs. `--plan-output <檔案>`**：在 `export-lang` 與 `create-pack` 中，`--output` 用來指定資源檔輸出的目標資料夾，`--plan-output` 則用來匯出 `nbtcli.patch-plan` 計畫檔。
- **`--format zip|directory`**：選擇輸出 `.zip` 壓縮檔或解開的資源包資料夾。
- **`--pack-format <major[.minor]>`**：明確指定 `pack.mcmeta` 中的 Minecraft `pack_format` 版本號（輸出至外部獨立目錄時必填）。
- **`--merge <路徑>`**：將產生的語言檔合併至既有的 ZIP 或資料夾資源包中。原有的美術貼圖、音效與 `pack.png` 皆會完整保留；若遇到衝突的翻譯鍵或內容不一致的檔案，會在寫入任何檔案前主動回報衝突並中止。
- **套用已保存的資源計畫檔**：當預覽時目標 `--output` 子資料夾尚未建立，計畫會綁定至最近一層已存在的父目錄（`physicalRoot`）。對已儲存的資源計畫執行 `apply` 時，請直接使用預覽 JSON 回傳的 `commitArguments`。

## 4. 單次世界文字轉翻譯鍵（`convert`）

若您不需要分頁人工翻譯，只想一次將世界內的現有文字轉為翻譯鍵並抽離成語言檔，請使用 `convert`：

```powershell title="PowerShell"
New-Item -ItemType Directory -Path 'D:\Plans' -Force | Out-Null
# 預覽轉換結果並匯出計畫檔
.\nbtcli.exe convert 'D:\WorldCopy' `
  --lang en_us `
  --prefix nbt. `
  --language-output 'resources.zip#assets/nbt/lang/en_us.json' `
  --output 'D:\Plans\convert-plan.json'
```

- 預設情況下，若多處文字具有完全相同的內容、角色、語境與佔位符簽章，`convert` 會共用同一個翻譯鍵；若希望每個實際出現位置都擁有獨立的翻譯鍵，請加上 **`--keepdup`**。
- 執行實際寫入（`--apply --world-offline`）時，`convert` 預設會先建立一份完整的世界備份並回傳 `convenienceBackupHash`（加上 `--no-backup` 僅會略過這份額外完整備份，底層強制的寫前備份與中斷復原日誌依然全程運作）。

## 5. 自訂實體名稱與引用同步（`--synchronize-references`）

在許多 Minecraft 冒險地圖中，指令方塊或函數（如 `@e[name=...]`）會透過實體或盔甲座的自訂名稱（`CustomName`）來鎖定目標。如果只翻譯了實體的 `CustomName` 卻沒有同步更新尋找該名稱的指令，地圖機關就可能失效。

為了保護地圖機關運作：

1. **預設安全攔截**：在一般的 `translate plan --direct`、`translate plan --keys` 與 `convert` 中，只要偵測到具識別作用的實體或盔甲座名稱被修改，預設會安全拒絕產出計畫，避免意外破壞 `@e[name=...]` 選擇器。
2. **有邊界的引用同步（`--synchronize-references`）**：在 `translate plan --direct` 模式下，若您確實要翻譯具識別作用的實體名稱，並希望工具自動將同一範圍內可證明匹配的指令引用一併更新，請加上 `--synchronize-references`：

```powershell title="PowerShell"
.\nbtcli.exe translate plan 'D:\WorldCopy' `
  --session-id 6f9619ff-8b86-d011-b42d-00cf4fc964ff `
  --revision 2 `
  --direct `
  --synchronize-references `
  --output 'D:\Translate\direct-sync-plan.json'
```

若範圍內有任何指令引用存在歧義、動態拼接或無法證明可安全改寫，規劃器會在修改任何檔案前立即中止並回報原因。
