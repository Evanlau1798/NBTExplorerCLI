<SafetyBanner tier="write" lang="zh-tw" />

**NBTExplorerCLI** 絕不會盲目覆寫你的 Minecraft 存檔。所有修改都採用**「先預覽計畫、後離線套用」**的兩步驟流程——就像網購結帳前先檢查購物車一樣。實際寫入硬碟前，工具也會自動在世界資料夾外保存原始檔案備份，就算中途發生意外中斷，也能安心復原或完整還原。

<WorkflowPipeline kind="edit" lang="zh-tw" />

## 1. 動手修改前的三個簡單原則

1. **永遠先用世界副本（例如 `D:\WorldCopy`）測試**，確認進遊戲沒問題再改正式存檔。
2. **執行 `apply` 或 `--apply` 前，先完全關閉 Minecraft**（以及其他地圖編輯器）。
3. **計畫檔與輸出檔都放在世界資料夾外面**（例如 `D:\Plans`），不要放在 `D:\WorldCopy` 裡。

---

## 2. 為什麼修改前要先執行 `get --types`？

Minecraft 存檔對資料型別非常嚴格——某個數字可能是 `Byte`（0 或 1）、`Short`、`Int` 或是文字 `String`。如果工具胡亂猜錯型別，存檔就可能讀不出來。

所以 NBTExplorerCLI 不讓你猜：只要先用 `get --types` 讀出原本的值（帶著正確的型別標籤），改掉裡面的內容，再交給 `set`，就能保證資料型別 100% 正確！

### 指定要改哪個欄位（`--pointer`）

用 `--pointer` 告訴工具欄位在哪裡，寫法跟資料夾路徑一樣用 `/` 串起來：

<Tabs syncKey="selector-kind">
  <TabItem label="一般路徑 (--pointer)">

```powershell title="PowerShell"
# 範例：讀取 level.dat 裡玩家背包第一格物品的 ID
.\nbtcli.exe get 'D:\WorldCopy' --path level.dat --pointer /Data/Player/Inventory/0/id --types
```

*（若欄位名稱本身含有 `~` 請寫成 `~0`，含有 `/` 請寫成 `~1`。）*

  </TabItem>
  <TabItem label="特殊符號欄位名 (--segments)">

如果標籤名稱含有句點、斜線等特殊字元，可以用 `--segments` 傳入明確的區段陣列：

```powershell title="PowerShell"
.\nbtcli.exe get 'D:\WorldCopy' `
  --path level.dat `
  --segments '[{"kind":"key","key":"Data"},{"kind":"key","key":"Custom.Key"}]' `
  --types
```

  </TabItem>
</Tabs>

*（修改 `.mca` 區塊檔時，請一併加上 `--chunk x,z`；若是針對獨立 `.mca` 檔操作，請再加上 `--dimension minecraft:overworld`。）*

## 3. 實戰示範：預覽並套用一次修改

<SafetyBanner tier="preview" lang="zh-tw" />

我們用「修改世界顯示名稱（`LevelName`）」當範例，每一行都幫你加上清楚說明：

<Tabs syncKey="plan-mode">
  <TabItem label="修改單一欄位 (set)">

```powershell title="步驟 1：產生預覽計畫（此時世界存檔完全不動！）"
# 1. 在世界外建一個資料夾放計畫檔
New-Item -ItemType Directory -Path 'D:\Plans' -Force | Out-Null

# 2. 讀取原本的 LevelName 並保留正確型別
$read = .\nbtcli.exe get 'D:\WorldCopy' --path level.dat --pointer /Data/LevelName --types | ConvertFrom-Json
if (-not $read.success) { throw $read.error.message }

# 3. 改成想要的新名稱並存成檔案
$replacement = $read.data.value
$replacement.data.root.value = '更新後的冒險地圖名稱'
$replacement | ConvertTo-Json -Depth 50 | Set-Content -Encoding utf8 'D:\Plans\new-level-name.json'

# 4. 建立預覽計畫（沒加 --apply，所以世界完全不會被動到）
.\nbtcli.exe set 'D:\WorldCopy' `
  --path level.dat `
  --pointer /Data/LevelName `
  --value-file 'D:\Plans\new-level-name.json' `
  --output 'D:\Plans\level-name-plan.json'
```

  </TabItem>
  <TabItem label="一次修改多個欄位 (plan / batch)">

如果要一次改多個欄位（最多 100,000 筆），建立一份 `nbtcli.operations` 檔案（**[完整命令參考](../command-reference/)** 內有現成產生腳本），再用 `plan` 建立批次預覽計畫：

```powershell title="PowerShell"
New-Item -ItemType Directory -Path 'D:\Plans' -Force | Out-Null

.\nbtcli.exe plan 'D:\WorldCopy' `
  --request 'D:\Plans\ops.json' `
  --output 'D:\Plans\batch-plan.json'
```

  </TabItem>
</Tabs>

計畫檔準備好之後，**確認 Minecraft 已經關閉**，再執行套用：

```powershell title="步驟 2：離線正式套用計畫"
.\nbtcli.exe apply 'D:\WorldCopy' `
  --plan 'D:\Plans\level-name-plan.json' `
  --world-offline `
  --output 'D:\Plans\level-name-receipt.json'
```

`apply` 在背後會自動幫你做完三件保護措施：
1. **先檢查檔案有沒有被別人改過**：如果建立計畫後存檔又被開過，會安全停止不硬寫。
2. **自動在世界資料夾外備份原檔**：保留最原始的檔案內容供隨時回滾。
3. **寫完立刻重新讀回驗收**：確認磁碟上的檔案跟計畫 100% 一致。

## 4. 萬一寫到一半視窗關掉或中斷怎麼辦？（中斷復原）

如果執行 `apply` 時不小心把終端機關掉，或看到退出碼 **`7`（`RECOVERY_REQUIRED`）**，別緊張！工具在動到檔案之前已經自動幫你存好備份。

照這三個步驟處理就好：

<Steps>

1. **千萬不要先開 Minecraft！**

   寫入還沒收尾前打開遊戲可能會改動區塊檔，讓復原變麻煩。請保持遊戲關閉。

2. **先用 `status` 看看目前狀態**

   從輸出訊息（或你存的 `plan.json`）複製 `planHash`（若有顯示 `data.pendingPlanHash` 則用那個），執行：

   ```powershell title="PowerShell"
   .\nbtcli.exe status 'D:\WorldCopy' `
     --plan-hash '<你的-PLAN-HASH>'
   ```

   *（如果原本有自訂 `--state-root`，記得在這裡也帶上同一個 `--state-root`。）*

3. **二選一：把剩下的寫完，或是整個還原回原狀（`recover`）**

   <Tabs syncKey="recover-mode">
     <TabItem label="繼續把修改做完 (預設)">

   安全接續完成剩下的修改：

   ```powershell title="PowerShell"
   .\nbtcli.exe recover 'D:\WorldCopy' `
     --plan-hash '<你的-PLAN-HASH>' `
     --world-offline
   ```

   完成後回傳退出碼 **`0`**。

     </TabItem>
     <TabItem label="取消這次修改，完整還原回原狀 (--rollback)">

   從寫前備份把世界逐位元組還原成 `apply` 執行前的樣子：

   ```powershell title="PowerShell"
   .\nbtcli.exe recover 'D:\WorldCopy' `
     --plan-hash '<你的-PLAN-HASH>' `
     --rollback `
     --world-offline
   ```

   還原成功會回傳退出碼 **`8`（`RolledBack`）**，方便你和腳本一眼區分「這是還原完成」而不是「正向套用成功」。

     </TabItem>
   </Tabs>

</Steps>

### 寫入引擎的四道流程

1. **前置雜湊檢查**：核對目標檔案 SHA-256 是否與計畫建立時一致（不一致回傳退出碼 `3` / `Conflict`）。
2. **寫前備份與候選暫存**：將原始位元組存入 `<stateRoot>\objects\` 並寫出候選暫存檔。
3. **發布復原日誌與原子替換**：在 `<stateRoot>\journals\` 紀錄交易日誌後替換目標檔案。
4. **讀回雜湊驗證**：重新讀取寫入後的檔案驗證與預期一致，最後標記 `"receiptIsTerminal": true`。

### 回執中的九種互斥結果計數

| 欄位名稱 | 代表意義 |
| --- | --- |
| `applied` | 已成功寫入磁碟並通過讀回驗證。 |
| `unchanged` | 原本就已經是這個值，確認無須寫入。 |
| `skipped` | 寫前檢查未通過，動到世界檔案前即已略過。 |
| `failed` | 準備或執行階段失敗。 |
| `conflict` | 建立計畫後目標檔案曾被改動，或發生操作衝突。 |
| `unsupported` | 該格式或結構不支援寫入。 |
| `cancelled` | 操作被中止（退出碼 `130`）。 |
| `recoveryRequired` | 寫入中途被中斷，請先執行 `status` 與 `recover`（退出碼 `7`）。 |
| `rolledBack` | `recover --rollback` 已將世界完整還原回修改前（退出碼 `8`）。 |

### 特殊復原情境備忘

- **測試驗證邊界**：復原機制已在 Windows NTFS 上通過程序終止測試；硬體瞬間斷電情境則不在已驗證保證範圍內。
- **`.nbtcli-pending-write` 標記**：待復原期間世界目錄內可能會有 `.nbtcli-pending-write` 標記，並阻擋新的寫入（回報 `data.pendingPlanHash`）。請保留此標記與外部狀態目錄，直到 `recover` 完成。
- **無法確認日誌時（`journalMayBeAbsent: true` 或 `receiptIsTerminal: false`）**：切勿把「未能確認日誌」當成「沒改到檔案」。請保持遊戲關閉、保留計畫與狀態目錄，確認原日誌與計畫身分後再決定執行 `recover` 或 `--rollback`。
- **解除 `Conflict` 寫入阻擋**：發生 `Conflict` 時工具會保留外部變更並維持阻擋；若你已在離線狀態將整份計畫檔案還原為經驗證的修改前版本，可重跑 `recover --rollback` 讓工具驗證相符後解除阻擋（同時保留原本的 `Conflict` 回執）。

</details>
