## 1. 支援的 Minecraft Java Edition 版本

**NBTExplorerCLI** 專為 **Minecraft Java Edition** 存檔設計（不支援基岩版）。隨時可以執行 `.\nbtcli.exe capabilities` 查詢工具內建的完整支援清單。

### 經典舊版 Anvil 存檔（`1.2.5`、`1.5.2`、`1.6.4`、`1.8.1`）

在 Minecraft 導入 `DataVersion` 之前的舊版 Anvil 存檔（儲存版本 `19133`）裡，檔案本身沒有標記確切的遊戲版本：
- **純讀取查閱**會自動支援（`java-classic-anvil`）。
- **翻譯或直接編輯**：在 `scan`、`extract`、`validate` 或 `translate start` 加上 `--minecraft-version` 告訴工具確切版本即可——支援 **`1.2.5`**、**`1.5.2`**、**`1.6.4`** 與 **`1.8.1`**：

```powershell title="範例：開始翻譯 Java 1.8.1 的經典冒險地圖"
.\nbtcli.exe translate start 'D:\ClassicWorldCopy' `
  --minecraft-version 1.8.1 `
  --source-language en_us `
  --target-language zh_tw
```

選定版本後，翻譯進度與直接更新計畫會自動記住這個版本。

<details>
<summary>經典舊版（1.2.5 / 1.5.2 / 1.6.4 / 1.8.1）字數限制與工作台配方檢查細節</summary>

- **Java 1.2.5**：支援直接修改原版告示牌（純文字，每行最多 15 個 UTF-16 碼元，不可換行）。
- **Java 1.5.2 與 1.6.4**：支援告示牌（每行最多 15 碼元、不可換行）、純文字書本（書名最多 16、每頁最多 256 碼元）、顯示欄位、計分板顯示名稱（最多 32）、隊伍前綴／後綴（各最多 16），以及可辨識的指令文字參數。
- **Java 1.8.1**：支援告示牌、書本、顯示欄位與可辨識的指令文字參數。
- 若實體名稱被當作指令選擇器的識別值，請保留原名；舊式內附資源包若不在翻譯範圍內，可用 `--types` 排除。套用後請務必用對應版本的原版遊戲實際測試。
- **工作台配方檢查**：對於資料包中的有序與無序工作台配方，若產物物品欄位缺漏、格式無效或設為空氣，`scan` 與 `validate` 會回報 `InvalidRecipeResult`。物品是否合法、材料與堆疊上限仍由對應版本的 Minecraft 伺服器驗證。

</details>

:::caution[發布地圖前，請務必進 Minecraft 遊戲實測！]
通過 `validate`、`scan` 或 `apply` 代表存檔檔案結構與雜湊校驗都正常，但**不能取代實際開遊戲測試**——像是告示牌字數會不會超出邊框、字型寬度與複雜指令的實機執行效果，都還是要親自進遊戲確認過再分享給玩家。
:::

## 2. 常見問題與排除步驟

### 狀況 1：PowerShell 說找不到 `nbtcli.exe` 或無法執行

**原因**：指令前面忘了打 `.\`、PowerShell 開在錯的資料夾，或是尚未把 `nbtcli.exe` 從 `.zip` 壓縮檔解壓縮出來。

<Steps>

1. 將完整發行 ZIP 解壓到一般資料夾（例如 `C:\Tools\nbtcli`），並將 `nbtcli.exe` 與隨附檔案保留在一起。
2. 在**該資料夾中**打開 PowerShell（點檔案總管網址列 -> 輸入 `powershell` -> 按 **Enter**）。
3. 執行時前面加上 **`.\`**：`.\nbtcli.exe --version`。
4. 如果第一次執行跳出 Windows SmartScreen 提示，點「**其他資訊**」->「**仍要執行**」。

</Steps>

### 狀況 2：檔案被鎖定或拒絕存取（退出碼 `5`）

**現象**：執行 `scan`、`backup` 或 `apply` 失敗，回報 `IO_ERROR` 或 `ACCESS_DENIED`。

<Steps>

1. 完全關閉 Minecraft 遊戲視窗、單人世界或本機伺服器。
2. 關閉其他正在開啟同一個世界資料夾的軟體（其他 NBT 工具、3D 地圖編輯器或壓縮軟體）。
3. 確認路徑沒有打錯，再對世界副本重試一次。

</Steps>

### 狀況 3：寫入途中中斷 — `RECOVERY_REQUIRED`（退出碼 `7`）

**現象**：執行 `apply` 時中途被關掉或回報 `RECOVERY_REQUIRED`。

<Steps>

1. **千萬不要先在 Minecraft 裡打開這個世界。**
2. 記下輸出中的 `planHash`（或 `data.pendingPlanHash`）與 `stateRoot`。
3. 先檢查狀態：`.\nbtcli.exe status 'D:\WorldCopy' --plan-hash <雜湊值>`。
4. 選擇繼續做完（`.\nbtcli.exe recover 'D:\WorldCopy' --plan-hash <雜湊值> --world-offline`）或一鍵完整還原回修改前（加上 `--rollback`，成功會回傳退出碼 `8`）。

</Steps>

### 狀況 4：建立計畫或開始翻譯後，世界曾被外部修改（退出碼 `3`）

**現象**：執行 `apply` 或 `translate submit` 回報 `CONFLICT`。

**原因**：產生計畫或開啟翻譯後，世界資料夾裡的檔案被其他程式動過了，所以工具拒絕用舊計畫硬蓋。

**解決方式**：
- **一般修改計畫**：對最新的世界重新執行 `get --types` 與 `set` / `plan`，產出一份新計畫檔。
- **翻譯進度過期**（提示 `repair: "start-new-session"`）：對更新後的世界副本開一個新的翻譯進度，再用 `translate memory` 沿用先前已經翻好的譯文（見 **[冒險地圖翻譯教學](../translation-workflow/)**）。

### 狀況 5：遇到損壞的區塊檔或未支援格式（退出碼 `4` 或 `5`）

**現象**：`scan` 或 `validate` 回報 `coverageComplete: false`，伴隨退出碼 `4`（格式尚未支援）或 `5`（檔案損壞，例如 0 位元組 `.mca` 檔或語法錯誤的資料包 JSON）。

<Steps>

1. 執行 `.\nbtcli.exe validate 'D:\WorldCopy'`，從輸出找出確切是哪一個檔案出問題。
2. 如果先前有建過備份，可以只還原那一個壞檔：`.\nbtcli.exe restore 'D:\WorldCopy' --manifest-hash <雜湊值> --path <相對路徑> --output 'D:\Backups\fix-plan.json'`，接著用 `apply --world-offline` 套用。
3. 若只想處理其他正常的維度或檔案，用 `--dimension`、`--region`、`--path` 或 `--types` 避開有問題的檔案即可。

</Steps>

### 狀況 6：超過大小或時間上限（退出碼 `6`）

**現象**：回報 `RESOURCE_LIMIT` 或 `PATTERN_TIMEOUT`。

**原因**：為了避免吃光記憶體或卡死，工具設有保護上限（輸出／檔案上限 64 MiB、單次最多 100,000 筆項目、深度最多 256 層、正規表示式上限 100 毫秒）。

**解決方式**：
- 用 `--dimension`、`--region`、`--path` 或 `--types` 分批處理。
- 翻譯時把 `--page-size` 或 `--page-bytes` 調小。
- 簡化 `--match-pattern` 的篩選語法。

## 3. 支援的 21 種地圖文字類型（`--types`）

執行 `scan`、`extract`、`validate`、`convert` 或 `translate start` 時，可用 `--types` 只挑想處理的文字種類（例如 `--types Sign,Book,ItemName`）：

- **方塊與告示牌**：`Sign`、`HangingSign`、`ContainerName`、`CommandBlock`
- **書本與講台**：`Book`、`LecternBook`、`Title`、`Author`
- **物品與實體**：`ItemName`、`ItemLore`、`ArmorStand`、`EntityName`、`TextDisplay`
- **計分板與 Boss 血條**：`BossBar`、`ScoreboardTeam`、`ScoreboardObjective`
- **資料包與語言資源**：`McFunction`、`Advancement`、`CommandStorage`、`LangKey`、`TranslationKey`
