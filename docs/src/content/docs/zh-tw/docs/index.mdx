**NBTExplorerCLI**（`nbtcli.exe`，版本 `1.0.0`）是專為 **Minecraft Java Edition** 世界（`1.12.2` 至 `1.21.11`，即 `DataVersion` `1343` 至 `4671`）打造的 Windows x64 獨立封裝命令列工具。無論是一般玩家、冒險地圖作者、翻譯團隊或自動化腳本開發者，都能透過它查閱 NBT 結構、掃描並翻譯世界文字、產生資源包，以及在離線狀態下安全套用經過驗證的修改。

## 適用場景與設計邊界

<CardGrid>
  <Card title="非常適合用於">
    - **冒險地圖翻譯與本地化團隊**：將散落於數千個告示牌、書本、物品、指令方塊與資料包中的文字整理為結構化分頁與術語表。
    - **技術型玩家、地圖作者與伺服器管理員**：在離線狀態下精確查閱或批次修改 `level.dat`、`.mca` 區塊、實體與資料包，並享有 SHA-256 前置檢查與自動寫前備份保護。
    - **自動化腳本與 AI Agent 整合**：透過單行確定性 JSON 回應與明確的結束代碼（`0` 至 `8` 及 `130`）驅動自動化查閱與翻譯管線。
  </Card>
  <Card title="不適用於">
    - **遊戲執行期間的即時連線修改**：所有會修改存檔的命令皆要求先關閉 Minecraft 與其他編輯器（並加上 `--world-offline`），以防止讀寫衝突損壞區塊。
    - **3D 地形視覺化預覽或圖形化方塊編輯**：本工具為專注於資料精確度與自動化管線的命令列引擎，不包含 3D 視窗介面。
    - **Minecraft 基岩版（Bedrock Edition）存檔**：本工具的儲存結構與 NBT 剖析器僅支援 **Minecraft Java Edition**。
  </Card>
</CardGrid>

## 認識三種操作安全等級

本網站的每篇教學與每一個 CLI 命令皆標示了清楚的「操作安全等級」，讓您在執行前一眼判斷該指令是否會動到您的 Minecraft 世界存檔：

| 安全等級標籤 | 對 Minecraft 世界存檔的影響 |
| --- | --- |
| **安全查閱：不改存檔** | 僅讀取檔案或檢查外部日誌狀態，絕不修改世界資料夾內的任何檔案。 |
| **預覽模式：僅產出計畫** | 在世界資料夾外的獨立目錄產出修改計畫（`nbtcli.patch-plan`）或儲存翻譯進度，世界存檔完全保持原狀。 |
| **修改存檔：請先關遊戲並備份** | 實際寫入世界資料夾。請務必先在「世界副本」上操作、確認已關閉 Minecraft 與其他編輯工具，並加上 `--world-offline`。 |

## 六大核心工作流程

建議依照以下順序閱讀指南，從第一次唯讀查閱開始，逐步掌握安全編輯、中斷復原與地圖翻譯流程：

<CardGrid>
  <Card title="1. 安裝驗證與安全查閱">
    核對發行包 ZIP 的 SHA-256 雜湊值、檢視 `candidate.json` 建置清單、解壓縮獨立封裝執行環境，並在世界副本上執行 `get`、`list`、`search` 與 `scan`。

    [前往安裝驗證與安全查閱 ->](./getting-started/)
  </Card>
  <Card title="2. 安全編輯與中斷復原">
    使用 JSON Pointer 或結構化區段選取目標節點，透過 `set`、`batch` 或 `plan` 預覽修改，在離線狀態下執行 `apply --world-offline`，以及透過 `status` 與 `recover` 處理中斷復原。

    [前往安全編輯與中斷復原 ->](./safe-editing/)
  </Card>
  <Card title="3. 地圖翻譯工作流">
    建立分頁翻譯工作階段（`translate start`）、匯出分頁（`export`）、提交譯文（`submit` / `advance`）、管理備註與術語表，並執行 `plan`、`apply` 與 `seal` 完成翻譯封存。

    [前往地圖翻譯工作流 ->](./translation-workflow/)
  </Card>
  <Card title="4. 資源包、語言檔與引用">
    比較直接改寫世界文字（`--direct`）、轉換為翻譯鍵（`--keys` 與 `convert`）、匯出獨立語言檔與資源包（`export-lang`、`create-pack`），以及同步外部引用（`--synchronize-references`）。

    [前往資源包、語言檔與引用 ->](./resources-and-packs/)
  </Card>
  <Card title="5. 備份與狀態檔管理">
    建立與驗證世界完整備份（`backup` 與 `restore`），並透過檔案樹結構了解世界資料夾外的外部快取（`cache/`）、工作階段（`sessions/`）、備份物件（`objects/`）與復原日誌（`journals/`）。

    [前往備份與狀態檔管理 ->](./backups-and-state/)
  </Card>
  <Card title="6. 支援範圍與疑難排解">
    查詢支援的 Minecraft Java Edition `DataVersion` 版本範圍、結束代碼（`0` 至 `8` 及 `130`）、剖析器驗證與遊戲內實測的責任邊界，以及常見錯誤排解方式。

    [前往支援範圍與疑難排解 ->](./support-and-troubleshooting/)
  </Card>
</CardGrid>

## 統一且可預測的單行 JSON 輸出

每次呼叫 `nbtcli.exe`，工具都會向標準輸出（`stdout`）寫入單行 UTF-8 JSON 物件：

```json title="stdout (nbtcli.cli)"
{
  "schemaFamily": "nbtcli.cli",
  "schemaVersion": 1,
  "success": true,
  "command": "version",
  "outcome": "Success",
  "data": {
    "product": "nbtcli",
    "version": "1.0.0"
  },
  "error": null
}
```

### CLI 介面訊息語言 vs. 地圖翻譯語言

NBTExplorerCLI 嚴格區分「工具本身的提示語言」與「Minecraft 世界內的文字語言」：

- **CLI 介面訊息語言（`--ui-locale`）**：可在任何命令前後加上 `--ui-locale zh-TW`（預設）或 `--ui-locale en-US`。此選項僅調整 `error.message` 與說明文字的語言，不會改變 JSON 欄位名稱、錯誤代碼或世界資料。
- **世界與資源包語言**：如 `--source-language`、`--target-language`、`--lang`、`--original-lang` 與 `--target-lang`，專門用於指定 Minecraft 語言代碼（例如 `en_us`、`zh_tw`）。
