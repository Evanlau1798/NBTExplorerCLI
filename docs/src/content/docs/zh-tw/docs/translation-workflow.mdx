<SafetyBanner tier="preview" lang="zh-tw" />

翻譯一張大型冒險地圖或自訂世界，往往需要處理散落在告示牌、書本、物品、實體、計分板、Boss 血條與資料包中的數百至數千筆文字。**NBTExplorerCLI** 提供了持久化的**分頁式翻譯工作階段（Translation Session）**工作流（`nbtcli translate`）。

所有工作階段進度與紀錄皆儲存在世界資料夾外的獨立狀態目錄中。在您最後一步明確對翻譯計畫執行 `apply --world-offline` 之前，您的 Minecraft 世界存檔完全不會被修改。

<WorkflowPipeline kind="translate" lang="zh-tw" />

## 1. 選用步驟：設定外部翻譯工具或 AI 助手偏好（`agent`）

若您搭配外部翻譯腳本或 AI 助手處理匯出的分頁，可先透過 `agent` 為該世界儲存預設的來源語言、目標語言與每頁筆數設定：

```powershell title="PowerShell"
New-Item -ItemType Directory -Path 'D:\Translate' -Force | Out-Null
# 匯出帶有版本標記的問卷範本
.\nbtcli.exe agent setup 'D:\WorldCopy' `
  --source-language en_us `
  --target-language zh_tw `
  --output 'D:\Translate\agent-questionnaire.json'

# 填寫 JSON 內的 agentName 與偏好欄位後提交儲存
.\nbtcli.exe agent submit 'D:\WorldCopy' `
  --request 'D:\Translate\agent-questionnaire.json'

# 隨時查詢目前已儲存的偏好設定
.\nbtcli.exe agent status 'D:\WorldCopy'
```

> [!NOTE]
> `agent` 命令僅在本機狀態資料夾內記錄設定，絕不會主動連線至任何外部網路服務，也不會自動取得修改世界存檔的權限。

---

## 2. 建立翻譯工作階段（`translate start`）

對您的世界副本執行 `translate start`，並指定 `--source-language` 與 `--target-language`（若已透過 `agent` 設定則可省略）：

```powershell title="PowerShell"
.\nbtcli.exe translate start 'D:\WorldCopy' `
  --source-language en_us `
  --target-language zh_tw `
  --page-size 30
```

您也可以搭配 `--dimension`、`--region`、`--types`、`--path` 或 `--match-pattern` 將翻譯範圍限定於特定區域或文字類型。

請從回傳的 JSON 中記下 `sessionId` 與初始的 `revision`（從 `0` 開始）：

```json title="stdout (translate start)"
{
  "schemaFamily": "nbtcli.cli",
  "schemaVersion": 1,
  "success": true,
  "command": "translate",
  "outcome": "Success",
  "data": {
    "status": {
      "sessionId": "6f9619ff-8b86-d011-b42d-00cf4fc964ff",
      "revision": 0,
      "total": 60,
      "pending": 60
    }
  },
  "error": null
}
```

### 認識翻譯槽位（Text Slots）的保護機制

- **每個實際出現位置都有獨立的 `slotId`**：即使兩塊告示牌寫著相同的英文句子，每個位置仍會分配到獨立的槽位，讓您能依遊戲場景語境分別調整譯文。
- **自動保護顏色格式與互動事件**：槽位僅暴露純文字部分；底層 JSON Text Component 的顏色、點擊與懸停事件（Click/Hover Events）、計分板變數與目標選擇器皆安全保留在本機工作階段中，避免因翻譯手誤而破壞指令語法。

## 3. 匯出分頁並提交譯文（`export`、`submit`、`advance`）

<Steps>

1. **匯出目標分頁（`export`）**

   將第一頁（`--page 0`）匯出至世界外的 UTF-8 檔案：

   ```powershell title="PowerShell"
   New-Item -ItemType Directory -Path 'D:\Translate' -Force | Out-Null
   $export = .\nbtcli.exe translate export 'D:\WorldCopy' `
     --session-id 6f9619ff-8b86-d011-b42d-00cf4fc964ff `
     --page 0 `
     --output 'D:\Translate\page-0-prompt.txt' | ConvertFrom-Json
   ```

   匯出的回應與檔案包含兩部分：
   - 唯讀的 `nbtcli.session-page` JSON 區塊，顯示每個槽位的原文、來源角色與語境群組。
   - 可供直接填寫並送回的 `nbtcli.session-reply` JSON 回覆範本。

2. **填寫匯出的回覆範本**

   請將實際回傳的 `data.replyTemplate` 另存為獨立檔案。保留原本的識別欄位，包含 `operationId`、`targetLocale` 與每個槽位的 `sourceTextHash`，並保留完整槽位清單。已翻譯的槽位請填 `"state": "translated"` 並在 `text` 填入譯文；若刻意保留原文不譯，請填 `"state": "unchanged"` 且 `"text": null`。

   ```powershell title="PowerShell"
   if (-not $export.success) { throw $export.error.message }
   $export.data.replyTemplate | ConvertTo-Json -Depth 50 |
     Set-Content -Encoding utf8 'D:\Translate\reply-0.json'
   ```

3. **提交回覆並推進至下一頁**

   <Tabs syncKey="submit-mode">
     <TabItem label="提交回覆檔 (submit)">

   ```powershell title="PowerShell"
   .\nbtcli.exe translate submit 'D:\WorldCopy' `
     --session-id 6f9619ff-8b86-d011-b42d-00cf4fc964ff `
     --reply 'D:\Translate\reply-0.json'
   ```

     </TabItem>
     <TabItem label="提交並取得下一待譯頁 (advance)">

   `translate advance` 可搭配 `--reply` 一次完成提交與取得下一頁，亦可不帶 `--reply` 直接查詢下一個待處理的分頁：

   ```powershell title="PowerShell"
   .\nbtcli.exe translate advance 'D:\WorldCopy' `
     --session-id 6f9619ff-8b86-d011-b42d-00cf4fc964ff `
     --reply 'D:\Translate\reply-0.json'
   ```

     </TabItem>
   </Tabs>

</Steps>

每次成功提交都會將工作階段的 `revision` 加 1（例如由 `0` 變為 `1`），並回傳下一個待處理分頁（`data.pendingPage`）。若以相同的 `operationId` 重複送出完全相同的回覆檔，系統會視為冪等操作並直接回傳既有收據。

> [!IMPORTANT]
> 每次提交回覆時，NBTExplorerCLI 都會檢查世界檔案是否與建立工作階段時的快照一致。若期間世界曾被外部修改，`submit` 會回傳結束代碼 `3`（`Conflict`）並提示 `"repair": "start-new-session"`，同時完整保留您已提交過的所有譯文紀錄供後續查閱。

## 4. 管理術語表、備註、翻譯記憶與重置

在翻譯過程中，您可以隨時查詢或維護輔助資訊：

- **查看翻譯進度**：`nbtcli translate status 'D:\WorldCopy' --session-id <guid>`
- **查詢單一槽位**：`nbtcli translate get 'D:\WorldCopy' --session-id <guid> --slot-id <slot-id>`
- **檢視語境群組**：`nbtcli translate groups 'D:\WorldCopy' --session-id <guid> --limit 50`
- **讀取術語表或譯者備註**：
  ```powershell title="PowerShell"
  .\nbtcli.exe translate glossary 'D:\WorldCopy' --session-id 6f9619ff-8b86-d011-b42d-00cf4fc964ff
  .\nbtcli.exe translate note 'D:\WorldCopy' --session-id 6f9619ff-8b86-d011-b42d-00cf4fc964ff
  ```
- **從舊工作階段查詢翻譯記憶（Translation Memory）**：
  ```powershell title="PowerShell"
  $previousSessionId = Read-Host '舊工作階段的 session ID'
  $slotId = Read-Host '目前工作階段的完整 slot ID'
  $glossaryVersion = Read-Host '術語表版本號'
  .\nbtcli.exe translate memory 'D:\WorldCopy' `
    --session-id 6f9619ff-8b86-d011-b42d-00cf4fc964ff `
    --slot-id $slotId `
    --source-sessions $previousSessionId `
    --glossary-version $glossaryVersion
  ```
- **跳頁或重置特定槽位**：將 `nbtcli.session-command` 格式的 JSON 檔案透過 `--request` 傳給 `translate jump`、`translate note`、`translate glossary` 或 `translate reset`（執行確認重置時需加上 `--confirm`）。

## 5. 產出計畫、離線套用並封存工作階段（`plan` -> `apply` -> `seal`）

當 `pending` 降為 `0`（所有槽位皆已標記為 `Translated` 或 `Unchanged`），請先透過 `translate status` 確認目前的 `revision` 編號，再依序完成最後三個步驟：

<Steps>

1. **產生翻譯修改計畫（`translate plan`）**

   <Tabs syncKey="translate-plan-mode">
     <TabItem label="直接替換世界內文字 (--direct)">

   直接將譯文寫入世界 NBT 與資料包檔案中：

   ```powershell title="PowerShell"
   .\nbtcli.exe translate plan 'D:\WorldCopy' `
     --session-id 6f9619ff-8b86-d011-b42d-00cf4fc964ff `
     --revision 2 `
     --direct `
     --operation-id 88888888-4444-4444-4444-121212121212 `
     --output 'D:\Translate\world-translate-plan.json'
   ```

     </TabItem>
     <TabItem label="轉為翻譯鍵並附加語言檔 (--keys)">

   將世界內文字轉為 `translate` 翻譯鍵並同步產生 `.json` 語言檔（詳見 [資源包、語言檔與引用](../resources-and-packs/)）：

   ```powershell title="PowerShell"
   .\nbtcli.exe translate plan 'D:\WorldCopy' `
     --session-id 6f9619ff-8b86-d011-b42d-00cf4fc964ff `
     --revision 2 `
     --keys `
     --prefix map. `
     --language-output 'resources.zip#assets/adventure/lang/zh_tw.json' `
     --operation-id 88888888-4444-4444-4444-121212121212 `
     --output 'D:\Translate\world-translate-plan.json'
   ```

     </TabItem>
   </Tabs>

   請記下回傳 JSON 中的 `planHash`。

2. **在離線狀態下套用計畫（`apply`）**

   <SafetyBanner tier="write" lang="zh-tw" />

   關閉 Minecraft 並套用剛剛產出的翻譯計畫：

   ```powershell title="PowerShell"
   .\nbtcli.exe apply 'D:\WorldCopy' `
     --plan 'D:\Translate\world-translate-plan.json' `
     --world-offline `
     --output 'D:\Translate\world-translate-receipt.json'
   ```

3. **封存翻譯工作階段（`translate seal`）**

   確認 `apply` 成功完成（結束代碼 `0`）後，帶入相同的 `--revision`、`--operation-id` 與 `--plan-hash` 封存工作階段：

   ```powershell title="PowerShell"
   $planHash = (Get-Content -Raw 'D:\Translate\world-translate-plan.json' | ConvertFrom-Json).data.planHash
   .\nbtcli.exe translate seal 'D:\WorldCopy' `
     --session-id 6f9619ff-8b86-d011-b42d-00cf4fc964ff `
     --revision 2 `
     --operation-id 88888888-4444-4444-4444-121212121212 `
     --plan-hash $planHash
   ```

   `translate seal` 會在磁碟上核對已完成且通過驗證的寫入日誌後，才將工作階段標記為已封存。若 `apply` 尚未執行或中途發生中斷，`seal` 會拒絕封存並引導您先執行 `status` 與 `recover`。

</Steps>
