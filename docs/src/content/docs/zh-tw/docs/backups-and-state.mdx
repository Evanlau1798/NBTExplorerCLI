**NBTExplorerCLI** 會將所有的工具紀錄、掃描快取、翻譯工作階段、備份資料塊（Blobs）與中斷復原日誌統一保存在**您的 Minecraft 世界資料夾之外**。這確保在查閱世界、建立掃描快取或進行翻譯時，絕不會在您的存檔資料夾內塞入額外的暫存檔。

## 1. 認識外部狀態目錄（`--state-root`）

預設情況下，與特定世界綁定的狀態檔會儲存在 Windows 本機應用程式資料目錄下：

<FileTree>
- %LOCALAPPDATA%\nbtcli\
  - worlds\
    - 4a8b9c1d2e3f... (無連字號之 world-id)
      - cache\ (供翻譯與寫入工作流使用的可重建掃描快取)
      - sessions\ (分頁翻譯工作階段、槽位回覆與術語表紀錄)
      - agent\ (外部翻譯輔助工具之預設語言與分頁偏好)
      - objects\ (以 SHA-256 內容定址的寫前備份與快照實體檔案庫)
      - journals\ (寫入交易日誌與最終完成收據)
      - backup_before-translation_20261118T070000Z_a1b2c3.json
  - scan\
    - 4a8b9c1d2e3f...\ (獨立執行 scan、extract、validate 時的預設快取)
</FileTree>

您也可以使用 `--state-root 'D:\NbtState\MyWorld'` 指定世界外的自訂資料夾。請注意，在執行相關聯的 `plan`、`apply`、`status`、`recover`、`backup`、`restore`、`translate` 與 `agent` 命令時，請務必帶入**相同**的 `--state-root`。

### 狀態目錄（State Root）內部結構一覽

| 子資料夾／檔案 | 用途說明 | 是否可刪除或重建？ |
| --- | --- | --- |
| `cache/` | 儲存翻譯與寫入流程使用的快取。 | **可重建**：與獨立的掃描快取（`scan --refresh` 更新之 `%LOCALAPPDATA%\nbtcli\scan\<world-id>`）分開管理。 |
| `sessions/` | 儲存翻譯工作階段（`translate start`、`submit`、`note`、`glossary`、`seal`）。 | **翻譯期間請保留**：內含您的翻譯進度、已提交譯文與術語表紀錄。 |
| `agent/` | 儲存外部輔助工具問卷設定（`agent setup` / `submit`）。 | **使用者偏好設定**：保留此目錄即可維持該世界的預設翻譯語言與分頁筆數。 |
| `objects/` | 以 SHA-256 內容定址的儲存庫，保存經雜湊驗證的寫前備份與完整備份內容。 | **還原與回滾必備**：`restore` 與 `recover` 必須依賴此目錄才能重建原始世界檔案。 |
| `journals/` | 儲存 `apply`、`status` 與 `recover` 使用的寫入日誌與完成收據。 | **中斷復原必備**：當寫入進行中或需要復原（結束代碼 `7`）時，切勿刪除。 |
| `backup_<suffix>_*.json` | 執行 `backup --suffix <名稱>` 時產生的具名備份清單。 | **請與 `objects/` 一併保留**：記錄世界備份中每個檔案的路徑與 SHA-256 雜湊值。 |

### 世界範圍綁定（Scope Binding）機制

`<world-id>` 是工具產生的無連字號世界識別碼。請為每一個世界副本指定各自獨立的 `--state-root`。如果您重新建立或複製了世界資料夾，請對該資料夾重新執行掃描並產生新的計畫檔。接續處理既有的復原日誌時，請使用相同的世界路徑與 `--state-root`。

## 2. 建立經雜湊驗證的世界備份（`backup`）

在進行大規模修改前，建議先執行 `backup` 為整個世界建立一份經雜湊驗證的完整備份（若只需備份單一檔案，可加上 `--path <相對路徑>`）：

```powershell title="PowerShell"
New-Item -ItemType Directory -Path 'D:\Backups' -Force | Out-Null
.\nbtcli.exe backup 'D:\WorldCopy' `
  --suffix before-translation `
  --output 'D:\Backups\before-translation-manifest.json'
```

```json title="stdout (backup)"
{
  "schemaFamily": "nbtcli.cli",
  "schemaVersion": 1,
  "success": true,
  "command": "backup",
  "outcome": "Success",
  "data": {
    "manifestHash": "4b227777d4dd1fc61c6f884f48641d02b4d121d3fd328cb08b5531fcacdabf8a",
    "stateRoot": "C:\\Users\\Player\\AppData\\Local\\nbtcli\\worlds\\4a8b9c...",
    "backupPath": "C:\\Users\\Player\\AppData\\Local\\nbtcli\\worlds\\4a8b9c...\\backup_before-translation_20261118T070000Z_a1b2c3.json",
    "namedManifestPublished": true
  },
  "error": null
}
```

> [!IMPORTANT]
> 備份清單 JSON 檔（`before-translation-manifest.json`）記錄的是檔案路徑與 SHA-256 雜湊值的**索引表**；實際的檔案位元組內容儲存在 `stateRoot` 下的 `objects/` 子資料夾中。請同時保留 `manifestHash` 與該 `stateRoot` 目錄，日後才能順利執行 `restore`。

## 3. 從備份還原世界檔案（`restore`）

<SafetyBanner tier="write" lang="zh-tw" />

`restore` 會根據備份清單與 `objects/` 儲存庫將世界（或透過 `--path` 指定的單一檔案）還原至備份時的狀態。即使目前世界內的目標檔案已經損壞或被誤刪，`restore` 依然能將其乾淨修復。

<Steps>

1. **預覽還原計畫**

   先不加 `--apply` 執行 `restore`，檢視預計還原的檔案清單：

   ```powershell title="PowerShell"
   .\nbtcli.exe restore 'D:\WorldCopy' `
     --manifest-hash 4b227777d4dd1fc61c6f884f48641d02b4d121d3fd328cb08b5531fcacdabf8a `
     --output 'D:\Backups\restore-plan.json'
   ```

2. **在離線狀態下套用還原計畫**

   關閉 Minecraft，並使用與預覽時相同的世界路徑與 `--state-root` 執行 `apply`。`apply` 會檢查預覽時記錄的前置狀態，拒絕覆寫在預覽之後才發生的外部變更：

   ```powershell title="PowerShell"
   .\nbtcli.exe apply 'D:\WorldCopy' `
     --plan 'D:\Backups\restore-plan.json' `
     --world-offline
   ```

   若預覽時有指定 `--state-root`，此處請一併帶入相同的選項。若只需修復單一損壞檔案，可在預覽命令加上 `--path level.dat`，檢視輸出的計畫檔後再執行 `apply`。

</Steps>
