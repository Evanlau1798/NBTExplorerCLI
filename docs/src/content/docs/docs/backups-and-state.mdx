**NBTExplorerCLI** keeps all of its own working files — scan caches, translation progress, backups, and recovery logs — **outside your Minecraft world folder**. That way, scanning a map or translating text never clutters your save folder with extra files.

---

## 1. Create a Backup Before Editing (`backup`)

Running `backup` saves a verified snapshot of your entire world (or just one file if you add `--path level.dat`) outside the world folder:

```powershell title="PowerShell"
New-Item -ItemType Directory -Path 'D:\Backups' -Force | Out-Null

.\nbtcli.exe backup 'D:\WorldCopy' `
  --suffix before-translation `
  --output 'D:\Backups\before-translation-manifest.json'
```

You will see output like this:

```json title="Output"
{
  "schemaFamily": "nbtcli.cli",
  "schemaVersion": 1,
  "success": true,
  "command": "backup",
  "outcome": "Success",
  "data": {
    "manifestHash": "4b227777d4dd1fc61c6f884f48641d02b4d121d3fd328cb08b5531fcacdabf8a",
    "stateRoot": "C:\\Users\\Player\\AppData\\Local\\nbtcli\\worlds\\4a8b9c...",
    "backupPath": "C:\\Users\\Player\\AppData\\Local\\nbtcli\\worlds\\4a8b9c...\\backup_before-translation_20261118T070000Z_a1b2c3.json",
    "namedManifestPublished": true
  },
  "error": null
}
```

Save the **`manifestHash`** (and `stateRoot`)!

:::caution[Keep Both the Backup Folder (`objects/`) and the `manifestHash`]
The `.json` file created by `backup` is only an **index list** of your files. The actual backed-up file contents live inside the `objects/` subfolder of `stateRoot`. Never delete `objects/` if you might want to restore later!
:::

## 2. Restore a Whole World or One Damaged File (`restore`)

<SafetyBanner tier="write" lang="en" />

`restore` can bring back your entire world — or repair a single damaged or deleted file (such as `level.dat`) — from a saved backup:

<Steps>

1. **Preview the Restore Plan**

   ```powershell title="PowerShell"
   # Preview restoring the whole world (add "--path level.dat" to restore only one file)
   .\nbtcli.exe restore 'D:\WorldCopy' `
     --manifest-hash '4b227777d4dd1fc61c6f884f48641d02b4d121d3fd328cb08b5531fcacdabf8a' `
     --output 'D:\Backups\restore-plan.json'
   ```

2. **Close Minecraft and Apply the Restore Plan**

   ```powershell title="PowerShell"
   .\nbtcli.exe apply 'D:\WorldCopy' `
     --plan 'D:\Backups\restore-plan.json' `
     --world-offline
   ```

   *(If you used a custom `--state-root` during backup/preview, pass that exact same `--state-root` here too.)*

</Steps>

## 3. Where `nbtcli` Stores Its Files (and What Is Safe to Delete)

By default, all external files live inside Windows' local app data folder (`%LOCALAPPDATA%\nbtcli\`):

<FileTree>
- %LOCALAPPDATA%\nbtcli\
  - worlds\
    - 4a8b9c1d2e3f... (one folder per world)
      - cache\ (fast scan cache for translation & editing)
      - sessions\ (saved translation progress & glossaries)
      - agent\ (optional saved language defaults)
      - objects\ (actual backup & undo data — KEEP!)
      - journals\ (write history & crash recovery logs — KEEP!)
      - backup_before-translation_20261118T070000Z_a1b2c3.json
  - scan\
    - 4a8b9c1d2e3f...\ (standalone cache for scan, extract, validate)
</FileTree>

### Quick Cleanup Guide

| Folder / File | What It Holds | Safe to Delete? |
| --- | --- | --- |
| `scan/` and `worlds/<id>/cache/` | Speeds up repeated scans. | **Yes.** Automatically rebuilt the next time you scan (or refresh with `scan --refresh`). |
| `sessions/` | Your translation progress, submitted pages, notes, and glossaries. | **Keep while translating.** Only delete once your map translation is completely done. |
| `agent/` | Saved default language/page preferences from `agent setup`. | **Optional.** Safe to delete if you no longer need saved defaults. |
| `objects/` & `backup_*.json` | The real backup file data used by `restore` and `recover --rollback`. | **Do NOT delete** if you want to restore backups or undo writes! |
| `journals/` | Active and past write logs used by `status` and `recover`. | **Never delete** if a write was interrupted (exit code `7`). |

<details>
<summary>Advanced: Using a Custom State Folder (--state-root) for Separate World Copies</summary>

If you keep multiple copies of the same map or want all tool files on another drive (for example `D:\NbtState\MyMap`), pass `--state-root 'D:\NbtState\MyMap'` to your commands.

- Always use the **same** `--state-root` across related `plan`, `apply`, `status`, `recover`, `backup`, `restore`, `translate`, and `agent` commands.
- Give each separate world copy its own `--state-root`, and generate fresh plans whenever you make a new copy of a world folder.

</details>
