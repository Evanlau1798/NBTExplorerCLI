Adventure maps often contain hundreds or thousands of lines spread across signs, books, named items, NPCs, scoreboards, bossbars, command blocks, and datapacks. **NBTExplorerCLI** collects all of that text into a **Translation Project (Session)** saved safely outside your world folder, splits it into small pages, and protects all colors, click events, and command syntax automatically.

Your Minecraft save is **not modified at all** until the final step when you explicitly apply your finished translation plan.

:::tip[Want an AI Assistant to Translate the Pages for You?]
You can follow this guide by hand, or hand our [`llms.txt`](../../llms.txt) manual to Claude, ChatGPT, Codex, or Cursor so it runs the export-and-submit loop for you! See **[AI Agent Quickstart](../ai-agents/)**.

## Step 1: Start a Translation Project (`translate start`)

Run `translate start` on your copied world folder (`D:\WorldCopy`), telling it the map's original language (`--source-language`), your target language (`--target-language`), and how many items you want per page (`--page-size`):

```powershell title="PowerShell"
.\nbtcli.exe translate start 'D:\WorldCopy' `
  --source-language en_us `
  --target-language zh_tw `
  --page-size 30
```

You will get back a JSON response like this:

```json title="Output"
{
  "schemaFamily": "nbtcli.cli",
  "schemaVersion": 1,
  "success": true,
  "command": "translate",
  "outcome": "Success",
  "data": {
    "status": {
      "sessionId": "6f9619ff-8b86-d011-b42d-00cf4fc964ff",
      "revision": 0,
      "total": 60,
      "pending": 60
    }
  },
  "error": null
}
```

Write down your **`sessionId`** — you will pass it to the next commands.
- `total`: Total number of text items found across the map.
- `pending`: How many items are still waiting to be translated.
- `revision`: Progress counter that goes up by `1` each time you submit a page.

:::note[Why Your Formatting and Commands Stay Safe]
Every individual sign line, book page, or item name gets its own `slotId`, so even two identical English lines can be translated differently depending on context. You only edit the plain text — underlying Minecraft colors, hover/click events, scores, and selectors are kept safely hidden inside the tool so a typo cannot break map mechanics.
:::

## Step 2: Export a Page and Fill In Translations

<Steps>

1. **Export Page 0 (`translate export`)**

   First create an external folder (`D:\Translate`) to hold your working files, then export page `0` and save its ready-to-fill reply file (`reply-0.json`):

   ```powershell title="PowerShell"
   # Create a working folder outside your world
   New-Item -ItemType Directory -Path 'D:\Translate' -Force | Out-Null

   # Export page 0 (replace the session ID with yours)
   $export = .\nbtcli.exe translate export 'D:\WorldCopy' `
     --session-id '6f9619ff-8b86-d011-b42d-00cf4fc964ff' `
     --page 0 `
     --output 'D:\Translate\page-0-prompt.txt' | ConvertFrom-Json

   if (-not $export.success) { throw $export.error.message }

   # Save the ready-to-fill reply template
   $export.data.replyTemplate | ConvertTo-Json -Depth 50 |
     Set-Content -Encoding utf8 'D:\Translate\reply-0.json'
   ```

   - `page-0-prompt.txt` shows each line's original text and where it appears (for example, a sign, a book, or an item name).
   - `reply-0.json` is the template you edit and send back.

2. **Fill In `reply-0.json`**

   Open `D:\Translate\reply-0.json` in Notepad or VS Code. Keep all ID fields (`operationId`, `sessionId`, `slotId`, `sourceTextHash`, etc.) unchanged, and keep every item in the `slots` list:
   - **If you translated an item**: set `"state": "translated"` and put your translation in `"text"`.
   - **If you want to keep the original text as-is** (such as a proper name or symbol): set `"state": "unchanged"` and `"text": null`.

3. **Submit the Completed Page (`submit` or `advance`)**

   <Tabs syncKey="submit-mode">
     <TabItem label="Submit This Page (submit)">

   ```powershell title="PowerShell"
   .\nbtcli.exe translate submit 'D:\WorldCopy' `
     --session-id '6f9619ff-8b86-d011-b42d-00cf4fc964ff' `
     --reply 'D:\Translate\reply-0.json'
   ```

     </TabItem>
     <TabItem label="Submit & Get Next Page Together (advance)">

   `translate advance` submits your finished reply and immediately returns the next unfinished page in one command (or call it without `--reply` anytime to see the next unfinished page):

   ```powershell title="PowerShell"
   .\nbtcli.exe translate advance 'D:\WorldCopy' `
     --session-id '6f9619ff-8b86-d011-b42d-00cf4fc964ff' `
     --reply 'D:\Translate\reply-0.json'
   ```

     </TabItem>
   </Tabs>

   Repeat Step 2 for each page until `pending` drops to **`0`**. You can stop anytime and continue another day — all progress is saved automatically outside your world.

</Steps>

:::caution[Do Not Edit the World While Translating]
Each time you submit a page, `nbtcli` checks that the world files have not changed since you started. If you edit the world externally mid-translation, `submit` stops safely with exit code `3` (`Conflict`) while keeping all your saved translations so you can start a new session and reuse them with `translate memory`.
:::

## Step 3: Apply Your Finished Translations to the Map

Once `pending` reaches `0`, check your latest `revision` number with `translate status`:

```powershell title="PowerShell"
.\nbtcli.exe translate status 'D:\WorldCopy' --session-id '6f9619ff-8b86-d011-b42d-00cf4fc964ff'
```

Then finish in three clear steps:

<Steps>

1. **Build the Update Plan (`translate plan`)**

   Choose how you want players to see the translation:

   <Tabs syncKey="translate-plan-mode">
     <TabItem label="Replace Text Directly in the Map (--direct)">

   **Easiest for players**: Writes translated text straight into the map so players do not need to install any resource pack:

   ```powershell title="PowerShell"
   $opId = [guid]::NewGuid().ToString()

   .\nbtcli.exe translate plan 'D:\WorldCopy' `
     --session-id '6f9619ff-8b86-d011-b42d-00cf4fc964ff' `
     --revision 2 `
     --direct `
     --operation-id $opId `
     --output 'D:\Translate\world-translate-plan.json'
   ```

     </TabItem>
     <TabItem label="Use Translation Keys + Resource Pack (--keys)">

   Converts map text into translation keys and bundles the matching `.json` language file inside a resource pack (see **[Resource Packs & Language Files](../resources-and-packs/)**):

   ```powershell title="PowerShell"
   $opId = [guid]::NewGuid().ToString()

   .\nbtcli.exe translate plan 'D:\WorldCopy' `
     --session-id '6f9619ff-8b86-d011-b42d-00cf4fc964ff' `
     --revision 2 `
     --keys `
     --prefix map. `
     --language-output 'resources.zip#assets/adventure/lang/zh_tw.json' `
     --operation-id $opId `
     --output 'D:\Translate\world-translate-plan.json'
   ```

     </TabItem>
   </Tabs>

   *(If you only want a standalone `.zip` resource pack without modifying the map at all, jump to **[Resource Packs & Language Files](../resources-and-packs/)** for `export-lang` and `create-pack`.)*

2. **Close Minecraft and Apply the Plan (`apply`)**

   <SafetyBanner tier="write" lang="en" />

   Make sure Minecraft is completely closed, then run:

   ```powershell title="PowerShell"
   .\nbtcli.exe apply 'D:\WorldCopy' `
     --plan 'D:\Translate\world-translate-plan.json' `
     --world-offline `
     --output 'D:\Translate\world-translate-receipt.json'
   ```

   Open your copied world in Minecraft to verify that signs, books, items, and dialogue look great in-game!

3. **Mark the Translation Project as Done (`translate seal`)**

   Once `apply` succeeds (exit code `0`), run `translate seal` with the same `--revision`, `--operation-id`, and the plan's `planHash`:

   ```powershell title="PowerShell"
   $planHash = (Get-Content -Raw 'D:\Translate\world-translate-plan.json' | ConvertFrom-Json).data.planHash

   .\nbtcli.exe translate seal 'D:\WorldCopy' `
     --session-id '6f9619ff-8b86-d011-b42d-00cf4fc964ff' `
     --revision 2 `
     --operation-id $opId `
     --plan-hash $planHash
   ```

   `seal` double-checks that the world update truly completed before closing the project.

</Steps>

## Draft Text From an Unresolved Source

Use `translate fallback` when a scan can read an artifact but cannot establish how its text is used. The draft includes the selected tag or line as context, candidate string paths, and a reply template. It works with NBT, JSON, SNBT, and UTF-8 text.

```powershell
.\nbtcli.exe translate fallback 'D:\WorldCopy' `
  --path 'datapacks/story/data/story/functions/dialogue.mcfunction' --line 12 `
  --output 'D:\Drafts\dialogue-context.json'
```

For an NBT file, use `--pointer` to select a tag, or omit it to inspect the root. A region lookup also needs `--chunk x,z` and a dimension when the input is a standalone region file. Use `--entry` for an exact ZIP member. Use `--format snbt` for a standalone SNBT snippet. Line numbers start at 1 and select a trailing structured command operand by default. For a fragment in an unfamiliar file, select `--byte-range start,length` using zero-based UTF-8 byte offsets and choose `--format json`, `snbt`, or `text` as appropriate. Explicit `--format text` produces a plain-text draft and reports `structureVerified: false`.

Copy `data.replyTemplate` to a separate JSON file. Fill in the `text` values for the slots you want to translate. Leave other values as `null`. Run the same selection again with `--reply` and a new output filename.

```powershell
.\nbtcli.exe translate fallback 'D:\WorldCopy' `
  --path 'datapacks/story/data/story/functions/dialogue.mcfunction' --line 12 `
  --reply 'D:\Drafts\dialogue-reply.json' --output 'D:\Drafts\dialogue-validated.json'
```

The result contains the translated snippet in `data.content`. The CLI matches the original source and selected slots, validates protected formatting, numbers, and private-use glyphs, and preserves other members of structured drafts. A line selection retains one physical line, including when the format can escape a newline inside a string. Place draft exports outside Minecraft world folders, even when selecting an individual file. The result reports `gameplayVerified: false`. Review the draft on a world copy before incorporating it into an edit. The fallback leaves the original artifact and scan verdict intact.

## Helpful Extras (Optional)

You do not need any of these to finish a map translation, but they are handy on large projects:

- **Translate only part of a map**: Add `--dimension`, `--region`, `--types`, `--path`, or `--match-pattern` to `translate start` (for example, `--types Sign,Book` to translate only signs and books).
- **Old classic Minecraft maps (1.2.5 / 1.5.2 / 1.6.4 / 1.8.1)**: Pass `--minecraft-version 1.8.1` (or `1.2.5`, `1.5.2`, `1.6.4`) to `translate start`. See **[Supported Versions](../support-and-troubleshooting/)** for plain-text character limits.
- **Check progress or view related lines**:
  - Progress: `.\nbtcli.exe translate status 'D:\WorldCopy' --session-id <id>`
  - One specific slot: `.\nbtcli.exe translate get 'D:\WorldCopy' --session-id <id> --slot-id <slot-id>`
  - Grouped context (same book/sign): `.\nbtcli.exe translate groups 'D:\WorldCopy' --session-id <id> --limit 50`

### Reading or Updating Glossary and Notes

```powershell title="PowerShell"
# Read saved glossary terms or translator notes
.\nbtcli.exe translate glossary 'D:\WorldCopy' --session-id '<session-id>'
.\nbtcli.exe translate note 'D:\WorldCopy' --session-id '<session-id>'
```

To add glossary terms, add notes, jump to a page, or reset selected slots back to unfinished, pass a `nbtcli.session-command` JSON file via `--request` to `translate glossary`, `translate note`, `translate jump`, or `translate reset` (add `--confirm` to execute a reset). See the template in **[Command Reference](../command-reference/)**.

### Reusing Translations From an Earlier Session (`translate memory`)

If the map was updated and you started a new translation session, look up matching translations from an earlier session:

```powershell title="PowerShell"
.\nbtcli.exe translate memory 'D:\WorldCopy' `
  --session-id '<current-session-id>' `
  --slot-id '<full-slot-id>' `
  --source-sessions '<previous-session-id>' `
  --glossary-version '<glossary-version>'
```

### Saving Default Languages for External Tools (`agent`)

If you reuse the same languages and settings on a world with scripts or AI tools, you can optionally store local preferences with `agent`:

```powershell title="PowerShell"
New-Item -ItemType Directory -Path 'D:\Translate' -Force | Out-Null

# 1. Export the preference questionnaire
.\nbtcli.exe agent setup 'D:\WorldCopy' `
  --source-language en_us `
  --target-language zh_tw `
  --output 'D:\Translate\agent-questionnaire.json'

# 2. Fill in configuration.agentName inside the file, then save it
.\nbtcli.exe agent submit 'D:\WorldCopy' --request 'D:\Translate\agent-questionnaire.json'

# 3. Check saved preferences anytime
.\nbtcli.exe agent status 'D:\WorldCopy'
```

`agent` commands only save settings locally inside your state folder — they never connect to the internet or modify your world.
