## 1. Supported Minecraft Java Edition Versions

**NBTExplorerCLI** works exclusively with **Minecraft Java Edition** saves (Bedrock Edition is not supported). You can always run `.\nbtcli.exe capabilities` to check the exact built-in support matrix.

### Versioned Java Saves (Detected Automatically)

`capabilities` reports all 17 format families with their inclusive `minimumDataVersion` and `maximumDataVersion`. Intermediate releases (for example, Java 1.20.3, 1.20.6, 1.21.1, and 1.21.4) resolve automatically to the matching family below. The table shows each family's inclusive `DataVersion` range and representative resource pack format. If `create-pack` cannot verify the world's default resource format, provide the correct `--pack-format` for your game version.

<ProfileTable lang="en" />

Older Anvil chunks store blocks and entities under `Level`. The scanner uses the layout stored in each chunk, including older chunks retained in a newer world. DataVersion 100–1513 uses read-only early Anvil profiles and exposes command block contents as raw text. Custom names, scoreboard names, and item lore switched to JSON independently at DataVersion 1458, 1514, and 1803, respectively.

The namespaced world layout introduced in 26.1 Snapshot 6 has an open upper bound in `capabilities` (`maximumDataVersion: null`). A later snapshot can reuse it when the save has the same layout and separate dimension registry. This has been verified on an original 26.4 Snapshot 10 save. Use `scan` to check coverage for the contents of a particular save.

Later datapacks and resource packs can reuse the same readers when their metadata and content follow the existing format. If `create-pack` cannot infer the output format, specify a verified format with `--pack-format`.

`scan` and full `validate` list recognized biome sound configuration issues in `data.compatibilityWarnings`, with the affected file and field. These settings are preserved byte-for-byte by translation. The matching Minecraft version still determines whether the sound plays.

### Classic Anvil Worlds

Older Minecraft Java Edition Anvil saves (storage version `19133`, before Minecraft added `DataVersion`) do not store an exact version number inside `level.dat`:
- **Read-only inspection** works automatically (`java-classic-anvil`).
- **Translating or direct editing**. Tell `nbtcli` the game version using `--minecraft-version` on `scan`, `extract`, `validate`, or `translate start`. The supported releases are **`1.2.5`**, **`1.5.2`**, **`1.6.4`**, and **`1.8` through `1.8.9`**.

```powershell title="Example: start translating a Java 1.8.1 adventure map (auto languages; add --source-language / --target-language to override)"
.\nbtcli.exe translate start 'D:\ClassicWorldCopy' `
  --minecraft-version 1.8.1
```

The translation session and its direct update plan record the format profile for the supplied release.

<details>
<summary>Limits for Classic Versions and Crafting Recipes</summary>

- **Java 1.2.5**: Supports direct edits to vanilla signs (plain text, up to 15 UTF-16 code units per line, no line breaks).
- **Java 1.5.2 and 1.6.4**: Supports signs (15 UTF-16 code units/line, no line breaks), plain-text books (title up to 16, each page up to 256 code units), display fields, scoreboard display names (up to 32), team prefixes/suffixes (up to 16 each), and recognized command text arguments.
- **Java 1.8 through 1.8.9** supports signs, books, display fields, and recognized command text arguments.
- Keep entity names used as command selector identifiers unchanged, use `--types` if a bundled classic resource pack is outside your scope, and always test in the matching vanilla Minecraft version.
- **Crafting Recipes**: For shaped and shapeless crafting recipes in datapacks, `scan` and `validate` report `InvalidRecipeResult` if the output item is missing, malformed, or air. Registry resolution, ingredients, and stack sizes are still verified by the matching Minecraft server.

</details>

:::caution[Always Test Your Edited World Inside Minecraft!]
Passing `validate`, `scan`, or `apply` confirms that the save files are structurally valid and uncorrupted, **not** how signs wrap visually, how custom fonts look, or how complex map commands behave during live gameplay. Always open your world copy in Minecraft and play-test before sharing your map!
:::

## 2. Common Problems & How to Fix Them

### Problem 1: PowerShell Says `nbtcli.exe` Is Not Recognized or Will Not Run

**What happened**: You typed `nbtcli` without `.\`, opened PowerShell in the wrong folder, or tried running it inside the compressed `.zip` preview without extracting first.

<Steps>

1. Extract the full release ZIP into a folder such as `C:\Tools\nbtcli`. Keep `nbtcli.exe` with its bundled files.
2. Open PowerShell **inside that exact folder** (click File Explorer's address bar -> type `powershell` -> press **Enter**).
3. Put **`.\`** in front of the command: `.\nbtcli.exe --version`.
4. If Windows SmartScreen pops up on first launch, click **More info** -> **Run anyway**.

</Steps>

### Problem 2: World File Is Locked or Access Denied (Exit Code `5`)

**What happened**: `scan`, `backup`, or `apply` failed with `IO_ERROR` or `ACCESS_DENIED`.

<Steps>

1. Close Minecraft (including any singleplayer world or local server) completely.
2. Close any other apps viewing the world folder (NBT viewers, 3D map editors, or ZIP tools).
3. Double-check the folder path, and run your command again on your world copy.

</Steps>

### Problem 3: Write Interrupted — `RECOVERY_REQUIRED` (Exit Code `7`)

**What happened**: `apply` stopped halfway (for example, the window was closed before finishing).

<Steps>

1. **Do NOT open the world in Minecraft.**
2. Copy `planHash` (or `data.pendingPlanHash`) and `stateRoot` from the output.
3. Check what happened: `.\nbtcli.exe status 'D:\WorldCopy' --plan-hash <hash>`.
4. Either finish the edit (`.\nbtcli.exe recover 'D:\WorldCopy' --plan-hash <hash> --world-offline`) or undo everything cleanly back to your original files (`.\nbtcli.exe recover 'D:\WorldCopy' --plan-hash <hash> --rollback --world-offline`, which returns exit code `8`).

</Steps>

### Problem 4: World Changed After Creating a Plan or Translation Session (Exit Code `3`)

**What happened**: `apply` or `translate submit` failed with `CONFLICT`.

**Why**: A file inside the world folder changed after you created the plan or started translating, so `nbtcli` blocked the write to prevent overwriting newer changes.

**How to fix**:
- **For an edit plan**: Re-run `get --types` and `set` / `plan` on the current world folder to create a fresh plan.
- **For a translation session** (`repair: "start-new-session"`): Start a new translation session on the updated world copy, then reuse your previous translations via `translate memory` (see **[Map Translation Guide](../translation-workflow/)**).

### Problem 5: Corrupted File or Unsupported Format (Exit Code `4` or `5`)

**What happened**: `scan` or `validate` reported `coverageComplete: false` with exit code `4` (unsupported format) or `5` (damaged file, such as a truncated `.mca` file or broken datapack JSON). Vanilla can leave empty entity and point-of-interest region files. The scanner reports these as `EmptyRegion`.

<Steps>

1. Run `.\nbtcli.exe validate 'D:\WorldCopy'` to see which exact file path had a problem.
2. If you have a backup, restore just that one file: `.\nbtcli.exe restore 'D:\WorldCopy' --manifest-hash <hash> --path <relative-path> --output 'D:\Backups\fix-plan.json'` followed by `apply --world-offline`.
3. If you only want to work on healthy parts of the map, limit the scope using `--dimension`, `--region`, `--path`, or `--types`.

</Steps>

### Problem 6: Size or Time Limit Hit (Exit Code `6`)

**What happened**: Output showed `RESOURCE_LIMIT` or `PATTERN_TIMEOUT`.

**Why**: To prevent out-of-memory crashes or runaway regexes, `nbtcli` enforces safety caps (64 MiB max output/file, 100,000 slots/ops, 256 nesting levels, 100 ms regex timeout).

**How to fix**:
- Split large worlds into smaller chunks with `--dimension`, `--region`, `--path`, or `--types`.
- Lower `--page-size` or `--page-bytes` when translating.
- Simplify complex `--match-pattern` filters.

### Problem 7: Language Detection, `und` Source, `--ui-locale`, or Fallback Reply Conflict

- **No usable system display language (Exit Code `2`)**: If Windows does not expose a usable display language when omitting `--target-language`, pass an explicit target such as `--target-language de-DE`.
- **Detected `sourceLocale` is `und`**: Short strings, proper names, or mixed-language content cannot be proven automatically. You can still translate by reading the original text, or start a new job with explicit `--source-language`. When exporting bilingual language files with `translate export-lang` or `translate create-pack` from a `und` session, pass `--original-lang <language>` explicitly.
- **Non-`en-US` `--ui-locale` rejected (Exit Code `2`)**: CLI help, errors, diagnostics, and translation prompt instructions are fixed in English. Remove `--ui-locale` or pass `--ui-locale en-US`.
- **`translate fallback --reply` returned `CONFLICT` (Exit Code `3`)**: Ensure you pass the exact same input selection and `--text-pointer` used when exporting the draft, keep `draftId`, `sourceLocale`, `targetLocale`, `slotId`, and `sourceTextHash` unchanged, and preserve protected placeholders, numbers, private-use glyphs, and Roman level suffixes.

## 3. All 21 Supported Map Text Categories (`--types`)

You can filter `scan`, `extract`, `validate`, `convert`, or `translate start` to specific kinds of map text using `--types` (for example, `--types Sign,Book,ItemName`):

- **Blocks & Signs**: `Sign`, `HangingSign`, `ContainerName`, `CommandBlock`
- **Books & Lecterns**: `Book`, `LecternBook`, `Title`, `Author`
- **Items & Entities**: `ItemName`, `ItemLore`, `ArmorStand`, `EntityName`, `TextDisplay`
- **Scoreboards & Bossbars**: `BossBar`, `ScoreboardTeam`, `ScoreboardObjective`
- **Map banner names** can be selected with `--types map.banner.name`.
- **Datapacks & Language Files**: `McFunction`, `Advancement`, `CommandStorage`, `LangKey`, `TranslationKey`
