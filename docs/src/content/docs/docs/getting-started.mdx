This guide walks you through downloading **NBTExplorerCLI**, verifying the archive checksum and provenance manifest, extracting the self-contained runtime, and running your first read-only inspection commands (`get`, `list`, `search`, `scan`, and `extract`) on a copy of a Minecraft Java Edition world.

## Setup and Verification Walkthrough

<Steps>

1. **Download and Verify the Windows x64 Archive**

   Obtain `nbtcli-win-x64.zip` and `SHA256SUMS.txt` from one of the two official channels:

   - **[GitHub Releases](https://github.com/Evanlau1798/NBTExplorerCLI/releases)**: Official tagged releases (`v1.0.0`) published through the release pipeline.
   - **[GitHub Actions Candidates](https://github.com/Evanlau1798/NBTExplorerCLI/actions)**: Automated build artifacts (`nbtcli-windows-x64`) verified in an SDK-free Windows Server Core container for a specific commit.

   Before extracting, confirm that the ZIP file's SHA-256 digest matches `SHA256SUMS.txt`:

   ```powershell title="PowerShell"
   $zipHash = (Get-FileHash .\nbtcli-win-x64.zip -Algorithm SHA256).Hash.ToLowerInvariant()
   $expected = (Get-Content .\SHA256SUMS.txt | Select-Object -First 1).Split(' ')[0].Trim().ToLowerInvariant()
   if ($zipHash -ne $expected) { throw "SHA-256 mismatch!" } else { "Verified OK: $zipHash" }
   ```

2. **Extract the Self-Contained Runtime**

   Extract the entire archive into a dedicated folder. The package bundles the pinned .NET runtime (`10.0.15`) and required libraries (`ICSharpCode.SharpZipLib.dll`). Always keep `nbtcli.exe` in the same folder as its accompanying `.dll` and `.json` files:

   ```powershell title="PowerShell"
   Expand-Archive -Path .\nbtcli-win-x64.zip -DestinationPath .\nbtcli
   Set-Location .\nbtcli
   ```

   > [!TIP]
   > Each release package includes `candidate.json`, which records the exact build version (`1.0.0`), Git commit revision, pinned SDK (`10.0.404`), dependency versions, and the SHA-256 digest of every bundled file.

3. **Check Binary Version and Command Help**

   Run `--version` and `--help` to confirm the binary launches cleanly:

   ```powershell title="PowerShell"
   .\nbtcli.exe --version
   .\nbtcli.exe --help
   ```

   ```json title="stdout (nbtcli --version)"
   {
     "schemaFamily": "nbtcli.cli",
     "schemaVersion": 1,
     "success": true,
     "command": "version",
     "outcome": "Success",
     "data": {
       "product": "nbtcli",
       "version": "1.0.0"
     },
     "error": null
   }
   ```

   To inspect accepted options for any root command, run `help <command>` (for subcommands such as `translate start`, pass `--help` at the end):

   ```powershell title="PowerShell"
   .\nbtcli.exe help get --ui-locale en-US
   .\nbtcli.exe help translate --ui-locale en-US
   .\nbtcli.exe translate start --help --ui-locale en-US
   ```

4. **Prepare a Disposable World Copy**

   Even though inspection commands never modify world files, always make a dedicated copy of your Minecraft world (for example, `D:\WorldCopy`) before testing queries, scans, or edits. Make sure Minecraft is closed while copying the save folder so all region and level files are flushed to disk.

</Steps>

## Inspecting Single Values with `get`

Use `get` to read a specific NBT tag, region chunk, datapack JSON property, or ZIP entry.

<Tabs syncKey="get-mode">
  <TabItem label="Display JSON (Default)">

By default, `get` returns concise, human-readable `display-json`:

```powershell title="PowerShell"
.\nbtcli.exe get 'D:\WorldCopy' --path level.dat --pointer /Data/DataVersion
```

```json title="stdout (display-json)"
{
  "schemaFamily": "nbtcli.cli",
  "schemaVersion": 1,
  "success": true,
  "command": "get",
  "outcome": "Success",
  "data": {
    "representation": "display-json",
    "tagType": "Int",
    "value": 3953
  },
  "error": null
}
```

  </TabItem>
  <TabItem label="Reversible Typed NBT (--types)">

If you plan to feed the result into `set` or `batch` later, add `--types` to obtain a reversible `nbtcli.typed-nbt` envelope inside `data.value` that preserves exact NBT tag types (`byte`, `short`, `int`, `long`, `float` raw bits, and typed arrays):

```powershell title="PowerShell"
.\nbtcli.exe get 'D:\WorldCopy' --path level.dat --pointer /Data/LevelName --types
```

```json title="stdout (typed-nbt)"
{
  "schemaFamily": "nbtcli.cli",
  "schemaVersion": 1,
  "success": true,
  "command": "get",
  "outcome": "Success",
  "data": {
    "representation": "typed-nbt",
    "tagType": "String",
    "value": {
      "schemaFamily": "nbtcli.typed-nbt",
      "schemaVersion": 1,
      "data": {
        "name": "",
        "root": {
          "tag": "string",
          "value": "Original Map Name"
        }
      }
    }
  },
  "error": null
}
```

  </TabItem>
</Tabs>

## Exploring Structure with `list` and `search`

Run `list` on a world directory to discover its declared dimensions, terrain region counts, and entity region counts:

```powershell title="PowerShell"
.\nbtcli.exe list 'D:\WorldCopy'
```

Run `list` on an `.mca` region file without `--chunk` to list populated chunk coordinates, or run `search` to find nodes by text value (`--query`), tag name (`--name`), or NBT tag type (`--type`):

```powershell title="PowerShell"
.\nbtcli.exe list 'D:\WorldCopy' --path 'region/r.0.0.mca' --limit 20
.\nbtcli.exe search 'D:\WorldCopy' --path level.dat --name Spawn --limit 10
```

## Scanning and Extracting World Text (`scan` & `extract`)

Use `scan` to index translatable and inspectable text across all 21 supported Minecraft text roles (signs, hanging signs, books, items, entities, containers, command blocks, functions, scoreboards, bossbars, advancements, and language files):

```powershell title="PowerShell"
# Quick summary of text sources across the world
.\nbtcli.exe scan 'D:\WorldCopy' --summary

# Scan a single dimension and include decoded text items in the output
.\nbtcli.exe scan 'D:\WorldCopy' --dimension minecraft:overworld --show-items --limit 25
```

> [!NOTE]
> Standalone `scan`, `extract`, and regular `validate` store their rebuildable cache outside your world folder under `%LOCALAPPDATA%\nbtcli\scan\<world-id>` by default (or a custom external `--cache-root`); translation and writing workflows use a separate cache under the state root. Pass `--refresh` to force re-parsing, or `--no-cache` to run without saving a persistent cache.

To export decoded text entries along with their exact source locations to an existing external folder, create the parent directory if needed and run `extract`:

```powershell title="PowerShell"
New-Item -ItemType Directory -Path 'D:\Exports' -Force | Out-Null
.\nbtcli.exe extract 'D:\WorldCopy' --unique --output 'D:\Exports\world-text-unique.json'
```

Now that you can safely inspect NBT nodes and scan world text, continue to **[Safe Editing and Recovery](../safe-editing/)** to learn how to preview and apply changes safely.
