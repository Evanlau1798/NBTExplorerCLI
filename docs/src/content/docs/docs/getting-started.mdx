This guide walks through downloading, extracting, and running your first read-only commands on a Minecraft Java Edition world copy.

## Part 1: Download and Set Up (Takes About 1 Minute)

<Steps>

1. **Download the Release ZIP**

   Go to the official **[GitHub Releases page](https://github.com/Evanlau1798/NBTExplorerCLI/releases)** and download the latest release **`.zip`** archive (wrapped in a `.zip` so browsers such as Chrome do not block direct `.exe` downloads).

   :::tip[No Extra Software Required]
   The ZIP includes the .NET runtime. Running `nbtcli.exe` requires no separate .NET or Java installation.
   :::

2. **Extract the Full ZIP**

   Right-click the downloaded `.zip` in File Explorer and choose **Extract All...**. Pick a simple folder path without special symbols, such as `C:\Tools\nbtcli`.

   Keep `nbtcli.exe` and its bundled files together in that folder.

3. **Open PowerShell Inside That Folder**

   Open `C:\Tools\nbtcli` in File Explorer, then use either of these easy shortcuts:
   - **Shortcut A**: Click the folder path bar at the top of File Explorer, type `powershell`, and press **Enter**.
   - **Shortcut B**: Hold **Shift**, right-click an empty space in the folder, and choose **Open in Terminal** (or **Open PowerShell window here**).

4. **Check That `nbtcli.exe` Works**

   In the PowerShell window, type the command below and press **Enter**:

   ```powershell title="PowerShell"
   .\nbtcli.exe --version
   ```

   You should see:

   ```json title="Output"
   {
     "schemaFamily": "nbtcli.cli",
     "schemaVersion": 1,
     "success": true,
     "command": "version",
     "outcome": "Success",
     "data": {
       "product": "nbtcli",
       "version": "1.0.0"
     },
     "error": null
   }
   ```

   :::note[If Windows SmartScreen Shows a Warning]
   Because this is an open-source GitHub release without a paid Microsoft signing certificate, Windows may show **"Windows protected your PC"** the first time you run it. As long as you downloaded it from the official GitHub Releases page above, click **More info** -> **Run anyway**.
   :::

   To see all available commands or help for a specific command (CLI help, diagnostics, and translation prompt instructions are always in English):

   ```powershell title="PowerShell"
   .\nbtcli.exe --help
   .\nbtcli.exe help get
   .\nbtcli.exe translate start --help
   ```

5. **Make a Safe Test Copy of Your Minecraft World**

   Even though read-only commands never touch your world, getting into the habit of testing on a copy keeps your original save 100% safe:
   1. **Close Minecraft completely** (so the game finishes saving every file).
   2. Press `Win + R`, type `%APPDATA%\.minecraft\saves`, and press **Enter** to open your Minecraft saves folder.
      *(Using Prism Launcher, CurseForge, or Modrinth? Open your instance folder and look inside its `saves` folder.)*
   3. Copy the world folder you want to explore and paste it somewhere easy to type, such as `D:\WorldCopy`.

</Steps>

## Part 2: Your First Safe Commands

All commands below leave `D:\WorldCopy` completely untouched (`list`, `get`, `search`, `scan`, and `extract` are **Read Only**; `translate start` is **Preview Only** and stores session state outside your world). Replace `D:\WorldCopy` with the path to your copied world folder.

### 1. See What Dimensions and Regions Exist (`list`)

```powershell title="PowerShell"
.\nbtcli.exe list 'D:\WorldCopy'
```

This shows you the dimensions inside the save (such as Overworld, Nether, and End) and how many region files (`.mca`) each one has.

### 2. Read a Specific Setting (`get`)

Let's read the world's name and Minecraft data version from `level.dat`:

```powershell title="PowerShell"
# Read the world's Minecraft DataVersion number
.\nbtcli.exe get 'D:\WorldCopy' --path level.dat --pointer /Data/DataVersion

# Read the world's display name
.\nbtcli.exe get 'D:\WorldCopy' --path level.dat --pointer /Data/LevelName
```

Parameters:
- `'D:\WorldCopy'` — Your copied world folder (wrap paths in single quotes `'...'`, especially if they have spaces).
- `--path level.dat` — Which file inside the world to open.
- `--pointer /Data/DataVersion` — Which field to read inside that file (works just like a folder path: `Data` -> `DataVersion`).

Example output:

```json title="Output"
{
  "schemaFamily": "nbtcli.cli",
  "schemaVersion": 1,
  "success": true,
  "command": "get",
  "outcome": "Success",
  "data": {
    "representation": "display-json",
    "tagType": "Int",
    "value": 3953
  },
  "error": null
}
```

Look at `data.value`: `3953` means Minecraft Java Edition `1.21`!

### 3. Search When You Do Not Know the Exact Path (`search`)

Not sure where a field is stored? Search by part of its name (`--name`) or text value (`--query`):

```powershell title="PowerShell"
# Find tags whose name contains "Spawn" inside level.dat
.\nbtcli.exe search 'D:\WorldCopy' --path level.dat --name Spawn --limit 10
```

### 4. Count and Export All Translatable Text (`scan` & `extract`)

If you want to see how much readable text exists across signs, books, items, entities, command blocks, scoreboards, and datapacks:

```powershell title="PowerShell"
# Show a quick summary count by text category
.\nbtcli.exe scan 'D:\WorldCopy' --summary
```

Want to save every unique text line into a JSON file you can open in Notepad or VS Code? First create an output folder **outside** your world, then run `extract`:

```powershell title="PowerShell"
# Create an external folder for exported files
New-Item -ItemType Directory -Path 'D:\Exports' -Force | Out-Null

# Export all unique text entries to D:\Exports\world-text.json
.\nbtcli.exe extract 'D:\WorldCopy' --unique --output 'D:\Exports\world-text.json'
```

:::tip[Why Create `D:\Exports` Outside the World?]
NBTExplorerCLI never allows writing export files or plan files inside your Minecraft world folder, so your save stays clean and uncluttered. Always point `--output` to an existing folder outside your world.
:::

### 5. Preview Your First Translation Project (`translate start`)

When starting a new map translation project, you can omit `--source-language` and `--target-language`. The CLI detects the source language from recognizable content (or uses `und` if undetermined), selects your current Windows account display language as the target, and displays and binds both languages to the session:

```powershell title="PowerShell"
# Automatic source detection + Windows account display language (Preview Only — world stays untouched)
.\nbtcli.exe translate start 'D:\WorldCopy' --page-size 30

# Override source and target explicitly when translating between other languages (for example, Japanese to German)
.\nbtcli.exe translate start 'D:\WorldCopy' --source-language ja-JP --target-language de-DE --page-size 30
```

- If Windows does not provide a usable display language, the CLI prompts in English to pass `--target-language <language>`.
- Bound languages stay locked to the session so you can resume later even if your system display language changes.
- If the detected source is `und`, you can still translate by reading the original text, or start a new session with an explicit `--source-language`.

<details>
<summary>Advanced: Inspecting Chunks (.mca), Datapacks, ZIP Packs, and Reversible Types (--types)</summary>

You can also inspect specific region chunks, datapack JSON files, or entries inside a resource pack ZIP:

<Tabs syncKey="target-kind">
  <TabItem label="Region Chunk (.mca)">

```powershell title="PowerShell"
# List generated chunk coordinates inside r.0.0.mca
.\nbtcli.exe list 'D:\WorldCopy' --path 'region/r.0.0.mca' --limit 20

# Read a field inside chunk (0, 0)
.\nbtcli.exe get 'D:\WorldCopy' --path 'region/r.0.0.mca' --chunk 0,0 --dimension minecraft:overworld --pointer /Status
```

  </TabItem>
  <TabItem label="Datapack JSON">

```powershell title="PowerShell"
.\nbtcli.exe get 'D:\WorldCopy' --path 'datapacks/custom/data/quest/advancement/root.json' --pointer /display/title
```

  </TabItem>
  <TabItem label="ZIP Resource Pack Entry">

```powershell title="PowerShell"
.\nbtcli.exe get 'D:\WorldCopy\resources.zip' --entry 'assets/custom/lang/en_us.json' --pointer /item.custom.sword
```

  </TabItem>
  <TabItem label="Typed Output (--types)">

Add `--types` when you plan to edit a value later with `set`. This preserves exact Minecraft NBT types (`byte`, `short`, `int`, `long`, `float`, `string`, etc.):

```powershell title="PowerShell"
.\nbtcli.exe get 'D:\WorldCopy' --path level.dat --pointer /Data/LevelName --types
```

  </TabItem>
</Tabs>

**About Scan Caching**: `scan`, `extract`, and `validate` automatically keep a fast, rebuildable cache outside your world under `%LOCALAPPDATA%\nbtcli\scan\<world-id>` so repeated scans are much faster. Pass `--refresh` to force a fresh scan, or `--no-cache` to skip saving a cache.

</details>
