This page lists every registered command and subcommand in **NBTExplorerCLI** (`nbtcli.exe`), aligned with the verified command surface contract (`nbtcli.command-surface`, version `1`).

## Global CLI Rules

For subcommand help (such as `translate start` or `agent setup`), append `--help` to the subcommand itself—for example `nbtcli translate start --help` (passing subcommands to `help`, such as `nbtcli help translate start`, exits with code `2`).

- **Single JSON Output**: Every command writes exactly one newline-delimited UTF-8 JSON envelope (`schemaFamily: "nbtcli.cli"`, `schemaVersion: 1`) to `stdout`.
- **Global Display Locale (`--ui-locale`)**: Pass `--ui-locale zh-TW` (default) or `--ui-locale en-US` before or after any command to select the language of error and help messages. It does not affect translation source/target locales (`--source-language`, `--target-language`, `--lang`, `--original-lang`, `--target-lang`).
- **Option Syntax**: Value options accept `--option value` or `--option=value`. Boolean flags take no value. Use `--` to end option parsing when a path begins with a hyphen.
- **Root and Option Aliases**:
  - Root `--help` and `-h` invoke `help`.
  - Root `--version` and `-v` invoke `version`.
  - `-h` is accepted as `--help` on any command.

## File and Standard Input (`-`) Schemas

Commands that read structured JSON from a file or standard input (`-`) validate the exact `schemaFamily` and `schemaVersion` before executing:

| Input Schema Family | Accepted By |
| --- | --- |
| `nbtcli.typed-nbt` | `set --value <json>` or `set --value-file <file\|->` |
| `nbtcli.operations` | `batch <file\|-> --world <dir>` or `plan <dir> --request <file\|->` |
| `nbtcli.patch-plan` | `apply <dir> --plan <file\|->` |
| `nbtcli.session-reply` | `translate submit --reply <file\|->` or `translate advance --reply <file\|->` |
| `nbtcli.session-command` | `translate jump`, `note`, `glossary`, or `reset` via `--request <file\|->` |
| `nbtcli.agent-questionnaire` | `agent submit <dir> --request <file\|->` |

Used by `nbtcli plan <world> --request <file|->` and `nbtcli batch <file|-> --world <world>`. Accepts 1 to 100,000 operations with unique `id` values.

To prepare a request for the simple string edit in the [editing guide](../safe-editing/), reuse the operations from its saved preview. For a batch, keep the source addresses for the same world and use distinct operation IDs.

```powershell title="Build an operation set from a preview"
$preview = Get-Content -Raw 'D:\Plans\level-name-plan.json' | ConvertFrom-Json
@{
  schemaFamily = 'nbtcli.operations'
  schemaVersion = 1
  data = @{ operations = @($preview.data.operations) }
} | ConvertTo-Json -Depth 100 | Set-Content -Encoding utf8 'D:\Plans\ops.json'
```

## PowerShell Automation & Exit-Code Pattern

When scripting `nbtcli.exe` in PowerShell or CI pipelines, parse the single-line JSON output with `ConvertFrom-Json` and check both `$LASTEXITCODE` and `$res.success`:

```powershell title="PowerShell"
$raw = .\nbtcli.exe get 'D:\WorldCopy' --path level.dat --pointer /Data/DataVersion --ui-locale en-US
$exitCode = $LASTEXITCODE
$response = $raw | ConvertFrom-Json

if ($exitCode -eq 7 -or $response.outcome -eq 'RecoveryRequired') {
  Write-Error "Interrupted write detected (planHash: $($response.data.planHash)). Run 'nbtcli status' and 'nbtcli recover'."
  exit 7
}

if ($exitCode -ne 0 -or -not $response.success) {
  throw "nbtcli failed (exit $exitCode, code $($response.error.code)): $($response.error.message)"
}

Write-Output "Detected DataVersion: $($response.data.value)"
```
