## Quick CLI Syntax Rules

- **Getting Help**: Run `.\nbtcli.exe help <command>` for root commands, or `.\nbtcli.exe <command> <subcommand> --help` for subcommands (for example, `.\nbtcli.exe translate start --help`). Running `nbtcli help translate start` exits with code `2`.
- **Shortcuts**: `--help` / `-h` works on any command; `--version` / `-v` prints the version.
- **CLI Message Language**: CLI help, errors, diagnostics, and translation prompt instructions are fixed in English. Passing `--ui-locale en-US` is accepted explicitly; any other value exits with code `2`. Map content translation works across any valid language tags.
- **Option Format**: Options with values accept `--option value` or `--option=value`. Use `--` before a path that starts with `-`.
- **Consistent JSON Output**: Every command prints exactly one single-line UTF-8 JSON object (`schemaFamily: "nbtcli.cli"`, `schemaVersion: 1`) to `stdout`.

## `translate` Subcommands

Session subcommands (`start` through `seal`) take `<world>` and accept `--state-root`, `--output`, `--help`, and `--ui-locale`. Single-selection `translate fallback` takes `<world-or-file>`. Batch `translate fallback <world> --batch <file>` accepts `--session-id` for session binding and `--state-root` for that session's custom state location. See the [batch workflow](../translation-workflow/#draft-text-from-an-unresolved-source-translate-fallback).

<summary>Advanced: Structured JSON Input Templates & PowerShell Automation Pattern</summary>

Commands that read structured JSON from a file (or `-` for standard input) enforce exact `schemaFamily` and `schemaVersion` (`1` for session/edit/agent schemas, `2` for `nbtcli.translation-draft-reply`) before running:

| Input Schema Family | Version | Accepted By |
| --- | --- | --- |
| `nbtcli.typed-nbt` | `1` | `set --value <json>` or `set --value-file <file\|->` |
| `nbtcli.operations` | `1` | `batch <file\|-> --world <dir>` or `plan <dir> --request <file\|->` |
| `nbtcli.patch-plan` | `1` | `apply <dir> --plan <file\|->` |
| `nbtcli.session-reply` | `1` | `translate submit --reply <file\|->` or `translate advance --reply <file\|->` |
| `nbtcli.translation-draft-reply` | `2` | `translate fallback <world-or-file> ... --reply <file\|->` |
| `nbtcli.translation-draft-batch` | `1` | `translate fallback <world> --batch <file\|->` ([schema example](../../llms.txt)) |
| `nbtcli.session-command` | `1` | `translate jump`, `note`, `glossary`, or `reset` via `--request <file\|->` |
| `nbtcli.agent-questionnaire` | `1` | `agent submit <dir> --request <file\|->` |

### Copy-Paste JSON Templates

<Tabs syncKey="input-schema">
  <TabItem label="nbtcli.typed-nbt">

Used by `set --value` or `set --value-file`. Always start from `data.value` returned by `nbtcli get <world> --path <rel> --pointer <ptr> --types` and modify only `data.root.value`:

```json title="value-typed-nbt.json"
{
  "schemaFamily": "nbtcli.typed-nbt",
  "schemaVersion": 1,
  "data": {
    "name": "",
    "root": {
      "tag": "string",
      "value": "Updated Map Title"
    }
  }
}
```

  </TabItem>
  <TabItem label="nbtcli.operations">

Used by `nbtcli plan <world> --request <file|->` and `nbtcli batch <file|-> --world <world>` (1 to 100,000 operations with unique `id` values). Reuse `data.operations` from a `set` preview to build a valid request quickly:

```powershell title="Build an operation set from a preview"
$preview = Get-Content -Raw 'D:\Plans\level-name-plan.json' | ConvertFrom-Json
@{
  schemaFamily = 'nbtcli.operations'
  schemaVersion = 1
  data = @{ operations = @($preview.data.operations) }
} | ConvertTo-Json -Depth 100 | Set-Content -Encoding utf8 'D:\Plans\ops.json'
```

Generated by `nbtcli agent setup <world> --output <file>`. Fill in `configuration.agentName`, retain IDs/revision, then submit via `nbtcli agent submit <world> --request <file|->`:

```powershell title="Export the questionnaire"

  --output 'D:\Translate\agent-questionnaire.json'
```

### PowerShell Scripting Pattern

```powershell title="PowerShell"
$raw = .\nbtcli.exe get 'D:\WorldCopy' --path level.dat --pointer /Data/DataVersion
$exitCode = $LASTEXITCODE
$response = $raw | ConvertFrom-Json

if ($exitCode -eq 7 -or $response.outcome -eq 'RecoveryRequired') {
  Write-Error "Interrupted write detected (planHash: $($response.data.planHash)). Run 'nbtcli status' and 'nbtcli recover'."
  exit 7
}

if ($exitCode -ne 0 -or -not $response.success) {
  throw "nbtcli failed (exit $exitCode, code $($response.error.code)): $($response.error.message)"
}

Write-Output "Detected DataVersion: $($response.data.value)"
```
