## Frequently Asked Questions

### Where are my Minecraft Java Edition worlds saved on Windows?

- **Official Minecraft Launcher**: Press `Win + R`, type `%APPDATA%\.minecraft\saves`, and press **Enter**. Each subfolder inside `saves` is one world.
- **Prism Launcher / MultiMC**: Right-click your instance -> **Folder** -> open `.minecraft\saves`.
- **CurseForge / Modrinth App**: Open your profile/instance -> click **Open Folder** -> open `saves`.

Always **copy** the world folder to another location (like `D:\WorldCopy`) while Minecraft is closed before experimenting!

### Do I need to install .NET or Java to run `nbtcli.exe`?

**No.** The release ZIP includes the .NET runtime. Extract the full ZIP and run `nbtcli.exe` from the folder containing its bundled files.

### Why did Windows show "Windows protected your PC" (SmartScreen)?

Windows SmartScreen flags new open-source `.exe` files that do not have a paid commercial signing certificate. As long as you downloaded the release `.zip` directly from the official [GitHub Releases](https://github.com/Evanlau1798/NBTExplorerCLI/releases) page, you can click **More info** -> **Run anyway**.

### Will running `nbtcli.exe` accidentally break my world?

NBTExplorerCLI has four layers of protection built in:
1. **Inspection commands never write to your world** (`get`, `list`, `search`, `scan`, `extract`, `validate`, `backup`).
2. **Editing commands default to Preview Only** — `set`, `plan`, `batch`, `convert`, `restore`, and `translate plan` only build a plan file outside your world without touching your save.
3. **Writing requires explicit confirmation** (`apply ... --world-offline`) while Minecraft is closed.
4. **Automatic backups before writing** — Before replacing any world file, `nbtcli` saves a copy of the original file outside your world and records a recovery journal so interrupted writes can be finished or rolled back cleanly.

Still, keeping your own copy of your world before editing is always the #1 best habit!

### Why does every command output JSON instead of normal text?

Structured JSON output makes it easy for both people and AI assistants / scripts to see exact results without messy formatting. To read any response quickly:
- Check `"success": true` (worked) or `"success": false` (stopped).
- Look inside `"data"` for the result.
- If it failed, read `"error"."message"` for the failure reason.

### How is this different from the classic GUI NBTExplorer?

- **Classic NBTExplorer** is a point-and-click tree window great for casually clicking around one or two tags by hand.
- **NBTExplorerCLI** is a command-line engine for **large jobs, multilingual adventure map translation, resource pack generation, crash-safe edits, PowerShell scripts, and AI agents**. It provides automatic previews and backups, and supports broad Java Edition format families (`DataVersion 100` through `4774+` plus classic Anvil worlds — see the [compatibility table](../support-and-troubleshooting/)).

### Does it work with Minecraft Bedrock Edition or modded worlds?

- **Bedrock Edition**: No — only **Minecraft Java Edition** saves are supported.
- **Modded Java worlds**: Read-only inspection (`get`, `list`, `search`) works on standard NBT tags, while translation and editing follow vanilla Java Edition schemas and fail safely if an unrecognized custom format is encountered. Always test on a world copy and verify inside the game.

### Can I let Claude, ChatGPT, Codex, or Cursor run `nbtcli.exe` for me?

**Yes!** That is one of its core strengths. Just give your AI assistant our dedicated manual URL (`https://nbtcli.evanlau1798.com/llms.txt`) or check **[AI Agent Quickstart](../ai-agents/)** for copy-paste prompts.

### What language are CLI messages in, and what languages can I translate maps between?

- **CLI messages**: Help, error messages, diagnostics, and translation prompt instructions are fixed in **English** (`--ui-locale en-US` is accepted explicitly; other `--ui-locale` values exit with code `2`).
- **Map content**: You can translate between any valid language tags. Omitting `--source-language` and `--target-language` automatically detects the source (or marks it `und`) and uses your Windows account display language as the target. Pass `--source-language` / `--target-language` whenever you want to override them (for example, `--source-language ja-JP --target-language de-DE`).

### What is `translate fallback` for?

When a scan can read a file or tag but cannot establish how its text is used in gameplay, `translate fallback` exports the selected tag or line as context along with editable text leaves and a versioned reply template (`nbtcli.translation-draft-reply` v2). If you know a custom field is displayed in-game, designate its relative path with `--text-pointer` (such as `/caption`) and repeat the same selection when validating `--reply`. Validated drafts report `gameplayVerified: false` and leave the original file and whole-world scan verdict untouched.

## Glossary

| Term | Description |
| :--- | :--- |
| **NBT** | Minecraft's save file format (Named Binary Tag). Think of it like a compact binary folder tree storing world settings, blocks, items, and entities. |
| **`level.dat`** | The main settings file in every Minecraft world folder (holds the world name, `DataVersion`, gamerules, spawn coordinates, etc.). |
| **Region File (`.mca`) & Chunk** | Minecraft divides the map into 16x16-block columns called **chunks**, and groups 32x32 chunks into `.mca` files inside `region/` or `entities/`. |
| **`DataVersion`** | A single integer Minecraft saves in `level.dat` that identifies the exact game version (for example, `3953` is Java `1.21`). |
| **JSON Pointer (`--pointer`)** | A slash-separated address pointing to one specific value inside a file, just like a folder path (for example, `/Data/LevelName`). |
| **Typed NBT (`--types`)** | Because Minecraft cares strictly about whether a number is a `Byte`, `Short`, `Int`, or `String`, `--types` saves that exact label alongside the value so edits never corrupt a tag. |
| **Patch Plan (`plan.json`)** | A read-only "preview blueprint" describing exactly which files and values will change. You create it first, check it, and only apply it when ready. |
| **Translation Session & Slot** | A saved translation project stored outside your world. Every individual sign line, book page, or item name becomes one numbered **slot** with bound source/target languages (`und` when source cannot be proven). |
| **Fallback Draft (`translate fallback`)** | A read-only context and reply-validation workflow (`nbtcli.translation-draft-reply` v2) for unresolved NBT, JSON, SNBT, or UTF-8 text snippets; supports relative `--text-pointer` for confirmed custom display fields. |
| **Translation Key (`--keys`)** | Replaces hard-coded text (like `"Welcome!"`) inside the map with a placeholder key (like `map.abc123`), while the actual words live in a resource pack `.json` language file so players can switch languages. |
| **State Root (`--state-root`)** | The external folder (by default inside `%LOCALAPPDATA%\nbtcli\`) where `nbtcli` keeps backups, translation progress, caches, and recovery logs — completely separate from your Minecraft world folder. |
| **`--world-offline`** | A safety switch required on commands that modify your world, reminding you to close Minecraft and any other editors first. |
| **Exit Code** | A small number (`0` through `8`, or `130`) returned when a command finishes. `0` means success; anything else tells scripts (and you) why it stopped. |
