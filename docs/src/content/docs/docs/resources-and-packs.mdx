When you finish translating a Minecraft Java Edition map, you can deliver the result in several different ways depending on how players will play your map. This page helps you pick the best option and walks through each one.

## 1. Which Output Style Should I Choose?

| Option | Command | Modifies Map Save? | Creates Resource Pack / Lang File? | Best For |
| --- | --- | --- | --- | --- |
| **Put Text Directly in the Map** | `translate plan --direct` -> `apply` | Yes | No | **Simplest for players.** Just open the map in Minecraft — no resource pack needed. |
| **Multi-Language Map (Keys + Pack)** | `translate plan --keys` -> `apply` | Yes | Yes | Players can switch languages by switching Minecraft's language setting with the map's resource pack. |
| **Standalone Resource Pack Only** | `translate create-pack` | No (if you pass external `--output`) | Yes (`.zip` or folder) | Creating or merging a client resource pack from a finished session without editing map NBT. |
| **Standalone Language JSON Only** | `translate export-lang` | No (if you pass external `--output`) | Yes (`en_us.json`, `zh_tw.json`) | Exporting raw `.json` language files to hand to translators or pack builders. |
| **One-Shot Convert Without Translating** | `convert <world> --lang <locale>` | Yes (when `--apply` is used) | Yes | Extracting an existing map's literal text into translation keys in one step. |

## 2. Converting a Translated Map to Translation Keys (`translate plan --keys`)

Instead of overwriting text with one fixed language, `--keys` turns every translated text slot into a Minecraft translation key (like `map.<id>`) and builds the matching `.json` language file in the **same** plan:

```powershell title="PowerShell"
New-Item -ItemType Directory -Path 'D:\Translate' -Force | Out-Null

.\nbtcli.exe translate plan 'D:\WorldCopy' `
  --session-id '6f9619ff-8b86-d011-b42d-00cf4fc964ff' `
  --revision 2 `
  --keys `
  --prefix map. `
  --language-output 'resources.zip#assets/adventure/lang/zh_tw.json' `
  --output 'D:\Translate\keys-plan.json'
```

Then close Minecraft and run `nbtcli apply 'D:\WorldCopy' --plan 'D:\Translate\keys-plan.json' --world-offline`.

### Where `--language-output` Writes the Language File

`--language-output` accepts three convenient formats inside your world folder:

- **`generated.zip#assets/example/lang/zh_tw.json`** — Creates a brand-new `.zip` resource pack if it does not exist yet.
- **`resources.zip#assets/example/lang/zh_tw.json`** — Safely merges your language file into the map's existing `resources.zip` while keeping all existing textures, sounds, and `pack.png`.
- **`resourcepacks/client/assets/example/lang/zh_tw.json`** — Writes or merges into an unpacked folder resource pack.

<FileTree>
- D:\Exports\Packs\adventure-pack.zip
  - pack.mcmeta
  - pack.png (kept intact when merging)
  - assets/
    - adventure/
      - lang/
        - **en_us.json** (original text)
        - **zh_tw.json** (your translations)
</FileTree>

:::note[Language Code Must Match]
The filename in `--language-output` (for example `zh_tw.json`) must match your session's target language, and an existing pack's `pack.mcmeta` must match your world's Minecraft version.
:::

## 3. Exporting Standalone Language Files or Resource Packs (`export-lang` & `create-pack`)

Once all slots in your translation session are finished (`pending: 0`), you can export standalone `.json` language files or a full `.zip`/folder client resource pack **without modifying any map gameplay data**.

:::caution[Always Pass an External `--output` Folder to Keep Your World Untouched]
If you leave out `--output`, `export-lang` defaults to writing inside `<world>\.nbtcli.language` and `create-pack` defaults to writing inside the world root or `<world>\resourcepacks`. Passing an explicit external folder like `--output 'D:\Exports\Packs'` guarantees your world folder stays completely untouched!
:::

<Tabs syncKey="pack-export-mode">
  <TabItem label="Build or Merge a Resource Pack (create-pack)">

```powershell title="PowerShell"
New-Item -ItemType Directory -Path 'D:\Exports\Packs', 'D:\Plans' -Force | Out-Null

# Preview first (omit --apply to preview, or add --apply --world-offline to write right away)
.\nbtcli.exe translate create-pack 'D:\WorldCopy' `
  --session-id '6f9619ff-8b86-d011-b42d-00cf4fc964ff' `
  --revision 2 `
  --original-lang en_us `
  --target-lang zh_tw `
  --prefix map. `
  --name 'adventure-pack.zip' `
  --format zip `
  --pack-format 34 `
  --merge 'D:\BaseAssets\base-pack.zip' `
  --output 'D:\Exports\Packs' `
  --plan-output 'D:\Plans\create-pack-plan.json'
```

  </TabItem>
  <TabItem label="Export Raw Language JSON Files (export-lang)">

```powershell title="PowerShell"
New-Item -ItemType Directory -Path 'D:\Exports\LangFiles', 'D:\Plans' -Force | Out-Null

# Preview standalone language file export
.\nbtcli.exe translate export-lang 'D:\WorldCopy' `
  --session-id '6f9619ff-8b86-d011-b42d-00cf4fc964ff' `
  --revision 2 `
  --original-lang en_us `
  --target-lang zh_tw `
  --prefix map. `
  --output 'D:\Exports\LangFiles' `
  --plan-output 'D:\Plans\export-lang-plan.json'
```

  </TabItem>
</Tabs>

### Important Options Explained Simply

- **`--output <folder>` vs. `--plan-output <file>`**: `--output` is where your generated `.zip` or `.json` files go; `--plan-output` is where the optional preview plan file is saved.
- **`--format zip|directory`**: Choose a `.zip` file (ready to drop into Minecraft's `resourcepacks` folder) or an unzipped folder.
- **`--pack-format <number>`**: Required when exporting outside the world so Minecraft recognizes the pack version (`22` for 1.20.4, `34` for 1.21, `55` for 1.21.5, `75` for 1.21.11, `80` for 26.1-snapshot-6).
- **`--merge <path>`**: Optional! Merges your new language files into an existing resource pack while preserving all textures, audio, and `pack.png`. If a translation key conflicts with an existing file, `nbtcli` stops and tells you instead of silently overwriting.

<details>
<summary>Advanced: Applying a Saved Resource Plan Later</summary>

To write immediately during `export-lang` or `create-pack`, simply add `--apply --world-offline`. If you preview first and run `nbtcli apply` later, use the exact `commitArguments` printed in the preview JSON (this matters when the target `--output` subfolder did not yet exist during preview).

</details>

## 4. One-Shot Key Conversion (`convert`)

Want to turn an English map's existing literal text straight into translation keys + `en_us.json` **without** creating a translation session? Use `convert`:

```powershell title="PowerShell"
New-Item -ItemType Directory -Path 'D:\Plans' -Force | Out-Null

# Preview the conversion plan first
.\nbtcli.exe convert 'D:\WorldCopy' `
  --lang en_us `
  --prefix nbt. `
  --language-output 'resources.zip#assets/nbt/lang/en_us.json' `
  --output 'D:\Plans\convert-plan.json'
```

- By default, identical text appearing in multiple places shares one translation key. Add **`--keepdup`** if you want every individual location to get its own separate key.
- When you apply `convert` (`--apply --world-offline`), it automatically takes a full-world convenience backup first (pass `--no-backup` only if you want to skip that extra convenience copy; crash-recovery backups remain active either way).

## 5. Keeping Command Blocks Safe When Translating Entity Names

In many adventure maps, command blocks look for specific armor stands or NPCs by their custom name — for example, `@e[name="QuestGuide"]`. If you translate `"QuestGuide"` without updating the command blocks that target it, quests and cutscenes can break!

To keep your map working properly:
1. **Protected by default**: Normally, if you try to translate an entity or armor-stand name used as an identifier, `translate plan` and `convert` refuse safely so you do not break map mechanics by accident.
2. **Automatic safe syncing (`--synchronize-references`)**: If you are using `translate plan --direct` and genuinely want to translate an entity name **and** automatically update every matching command reference in scope, add `--synchronize-references`:

```powershell title="PowerShell"
.\nbtcli.exe translate plan 'D:\WorldCopy' `
  --session-id '6f9619ff-8b86-d011-b42d-00cf4fc964ff' `
  --revision 2 `
  --direct `
  --synchronize-references `
  --output 'D:\Translate\direct-sync-plan.json'
```

If any command reference is dynamic or ambiguous (meaning it cannot be guaranteed safe to rewrite), planning stops before touching your world.
