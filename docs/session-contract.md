# Translation session exchange

`TranslationSessionService` owns start, export, submit and validated-page reads.
It stores decoded text slots bound to one world/source snapshot. A verified query
can supply real source occurrences; the source manifest, complete local addresses,
text revisions, locales and policy remain in the session record.

## Wire boundaries

The page, reply and local session use separate schema families, each at version 1:
`nbtcli.next.session-page`, `nbtcli.next.session-reply` and
`nbtcli.next.translation-session`. They use the shared strict, lossless UTF-16
contract codecs. Unknown versions, fields, duplicate members and invalid states
are rejected. The default contract limit is 64 MiB and one million JSON tokens.

Pages expose slot and snapshot digests, decoded source text, context, allowed-empty
and placeholder policies. Full canonical identities and addresses stay local.
A page digest binds its session/revision/snapshot/page/locales/policy and ordered
slot contents. The prompt embeds a reply template generated by the same writer
used by the import parser. Replies contain operation ID, all binding fields and
the exact complete slot set. Reply order does not choose source pairing.

`translated` requires a string; an allowed empty string remains a translation.
`unchanged` requires null text and explicitly means no translation is requested.
There is no implicit partial-page submission. Missing, extra or duplicate slots,
wrong source hashes or stale bindings reject the whole page and leave its head
unchanged. Reply text is data, including `|`, `‖§‖`, `{{T0}}`, quotes and controls.
Replies cannot declare AST nodes, events, styles, UUIDs, addresses or PatchKind.

## Formatting contracts

The accepted literal placeholder contract preserves each declared token's ordinal
multiplicity and allows reordering. An explicit ordered policy additionally checks
the token sequence, including overlapping tokens, with ordinal tie ordering.
Unlisted markers are ordinary text.

Known Minecraft `language.value` slots use `normalizedPercent`: the language
loader's numeric conversion produces string arguments before percent parsing.
Component `.fallback` slots use raw `percent`. Their independent implicit counter,
positive explicit indices, escaped percent and literal-fallback behavior follow
the fixed official formatter profiles. A translation must preserve the same active
argument indices and multiplicities; indexed argument reordering is allowed.
The known source grammar is assigned locally and cannot be downgraded by a reply
or overridden by start policy. It is retained in the start hash, slot state and
page digest, and checked again when persisted replies are read.

The four supported source profiles have matching formatter constants. The
project-authored Java Pattern/Integer reference generates 2,312 fixed comparison
pairs independently of the bounded C# scanner; see `tests/oracles/README.md`.
Invalid formatting uses the formatter's whole-string literal fallback, with no
active argument contract. Text and occurrence limits fail explicitly rather than
being treated as that fallback.

## Fixed pages and durable state

Policy controls maximum page slots and actual UTF-8 bytes of the complete prompt,
source page and reply template. Defaults are 30 slots and 64 KiB. Stored membership
is fixed using the maximum revision width, so later revision growth cannot silently
move slots between pages. A single oversized slot raises an explicit outcome; no
unaligned splitting or partial initial session is saved.

The local head contains source slots, fixed page membership, per-slot status and a
contiguous revision/operation ledger. It retains the original submitted reply bytes
as Base64 with their hash. Replaying that ledger through the same validator must
produce exactly the stored translated/unchanged states. Initial slots are pending.
The session bound is 100,000 slots and operations, with separate document limits;
large scan capacity does not guarantee one full-world session fits that document.
Decoded reply text is bounded to 64 MiB. Declared literal tokens are bounded to 256
per slot; ordered/percent occurrences are bounded to 100,000, with percent text
bounded to 64 MiB of UTF-16 code units.

An owned, guarded local NTFS directory stores one atomic head per session. Writes
validate the record/session identity, then use stage/flush/verify/CAS/readback.
Shared-instance operations serialize that complete write; separate instances and
processes retain the filesystem writer lease. A foreign directory is refused.

Start binds an operation ID to canonical start input. Submit binds its operation ID
to the exact raw reply bytes, including whitespace. An already saved identical
operation returns its durable receipt before stale-revision checks; another input
using that ID conflicts. A losing revision CAS cannot overwrite the winning head.
There is no automatic resubmission with a changed revision.

Flush failure or process interruption before replace retains the old complete head;
interruption after save retains the new complete head and receipt. Retained input
allows an explicit retry to recover the same operation. The API does not delete
reply files. Unreferenced candidates from a killed process may remain in owned
state; they are not an alternative head or recovery authority.

## Scope of this service

Session persistence and text validation do not write world files. A source snapshot
may accurately retain incomplete extraction/reference coverage; its identity is
not a current-world lock or write authorization. Apply must independently verify
current raw preimages, supported write profiles, protected structure and required
reference groups. Navigation, grouping, TM, notes/reset, legacy import and public
CLI integration have their owning contracts beyond this exchange/persistence API.
Implemented legacy retention and conservative reconstruction are documented in
`legacy-mapping-contract.md`; source snapshots still confer no world-write authority.

## Context and work management

Status distinguishes pending, translated, explicitly unchanged, conflict and applied
counts; translated text does not count as a world write. Get uses an exact slot digest.
Next reads the first pending page at or after the navigation cursor, wrapping once;
it does not repeatedly regenerate a reply or change completion. A complete session
has no pending page. Jump changes only the cursor and is a revisioned command.

Note and glossary commands append text with origin and confirmation status. They
retain existing entries and never change source text, slot identities or selector
authorization. Reset first exposes a preview with exact slot IDs and revision. Its
command requires explicit confirmation and exact nonempty slot scope. It clears
only current progress/reply for those slots; all past reply inputs and receipts,
notes, glossary, sources, page membership and cursor survive. Operation replay
prevents duplicate effects and changed-input reuse conflicts.

Management commands use `nbtcli.next.session-command` version 1. Their raw canonical
input joins replies in the same atomic revision ledger. State validation replays
both command and reply history and checks the final workspace and slot states.
An optional workspace member keeps the previous version-1 session wire bytes
unchanged until the first management command; old records remain readable.

Groups have a source container, GroupId, ordered slot digests and member digest.
They preserve numeric book page and sign line order and component text before its
extra fragments. Every slot retains its original complete address; groups never
join strings or proportionally split a translated string. Fixed source membership
uses membership revision zero and survives navigation/translation revisions.

Explicit command-storage component rules carry their exact root paths through the
opaque query result into optional `source.contextRoots` session bindings. Warm cache
hits retain the same rule policy, and restarting a session preserves each binding.
Storage literals stay independent even when their keys are `text`, `extra` or `pages`.
Root bindings must reference an existing component slot in the same artifact,
dimension and chunk, with a containing physical path; duplicate/foreign bindings
are rejected. Missing bindings in an older manually assembled storage-component
session produce an explicit grouping error requesting a rescan, rather than a
guessed group. Other session operations remain available. Records without bindings
retain their previous version-1 wire bytes; bindings add no world-write authority.

Memory lookup accepts an explicit bounded set of source sessions. It returns
validated translated slots as separate candidates, with source session, slot,
revision and provenance. Its key binds decoded source, source/target locales,
context class, placeholder contract, glossary version and profile version.
Identical source text in another context does not force a match. The caller must
explicitly select a candidate and submit it through the normal validator; lookup
never updates a slot. Notes and glossary confirmation are not rename authority.

Notes/glossary permit at most 10,000 entries each, 16,384 UTF-16 units per text and
1,024 for origins. Memory lookup accepts up to 256 distinct source sessions and
100,000 candidates. The existing session JSON/token/operation budgets remain in
force. Legacy input retention/mapping has its own import contract.
